# Issue

1. 단추를 하나 더하니 줄 전체가 위로 밀렸다
    - 증상
        - 레이드를 더했더니 단추 줄이 위로 올라갔다. 사용자가 [조금 내려 달라] 고 했다
    - 원인
        - 자리를 **맨 위 단추** 기준으로 잡고 아래로 세었다. 그래서 개수가 늘면 줄이 위로 자란다
        - 비율로 옮기면서(R2-131) 옛 값을 그대로 옮겼고, 그 값이 맨 위 기준이었다
    - 처리
        - 기준을 **줄 전체의 가운데** 로 바꿨다. 몇 개가 되어도 줄이 같은 자리에 선다
        - **개수가 변하는 것의 자리는 끝이 아니라 가운데를 기준으로 잡는다.** 끝을 기준으로 잡으면 개수가 곧 자리가 된다

2. 새 화면을 더할 때마다 순환 참조가 하나 늘어난다
    - 증상
        - 순환 참조 경고가 넷에서 다섯이 됐다
    - 원인
        - 화면이 길 안내를 들고, 길 목록이 화면을 들여온다. 화면을 더하면 그 짝이 하나 더 생긴다
        - 기존 넷과 똑같은 모양이라 새로 생긴 문제가 아니다. 다만 **화면 수에 비례해 늘어난다**
    - 처리
        - 이번 티켓에서는 안 고쳤다. 따로 세운다 (R2-133)
        - **같은 모양의 경고가 늘어나는 것은 하나하나가 아니라 구조를 봐야 한다는 표다**

## 로비의 넷을 그대로 따라갔다

| 자리 | 로비 | 레이드 |
| --- | --- | --- |
| 값 | `LobbyMenuFrame` | `RaidPlaceholderFrame` |
| 그리기 | `LobbyMenuRenderer` | `RaidPlaceholderRenderer` |
| 다루기 | `LobbyMenuControl` | `RaidPlaceholderControl` |
| 차리기 | `TCGMainLobbyView` | `TCGRaidView` |

**따라가 보니 됐다.** 로비에서 정한 것이 로비만의 것이 아니었음을 한 번 확인한 셈이다.

로비에서 겪은 것도 따라왔다 — 다시 들어올 때 **다시 만들지 않는다.** 로비에서 그 버그를 고친 뒤라 레이드는 처음부터 그렇게 만들었다.

## 그림 없는 단추

```
{type: Raid, imageSrc: null, label: '레이드'}
```

그림이 생기면 `imageSrc` 를 채우고 `label` 을 `null` 로 바꾸면 끝이다. 렌더러가 이미 둘 다
그린다.

**글자 그리는 것을 지우지 않는다.** 새 메뉴를 붙일 때마다 그림보다 글자가 먼저 나온다.
지우면 다음에 또 만든다.

## 레이드 기능은 이 자리를 키워서 만들지 않는다

지금 있는 것은 [준비 중] 을 알리는 글자 한 덩이다. 실제 기능이 붙으면 **이 자리 옆에**
그 기능을 다루는 자리가 생긴다. 주석에 그렇게 적어 두었다 — 안 적으면 준비 중 알림을
키워서 레이드를 만들게 된다.

| 구분 | 내용 |
| --- | --- |
| **잘 맞은 것** | 로비의 넷을 그대로 따라갔고 됐다. 방식이 하나라는 것이 확인됐다. |
| **잘 맞은 것** | 그림이 없다고 멈추지 않았다. 글자로 두고 나중에 갈아 끼울 수 있게 했다. |
| **잘 맞은 것** | 단추 줄 기준을 끝에서 가운데로 바꿨다. 다음에 메뉴가 늘어도 안 밀린다. |
| **미흡한 것** | 순환 참조를 하나 더 만들었다. 기존과 같은 모양이지만 화면 수에 비례해 늘어난다. |
| **다음 작업에 넘길 것** | 화면을 더할 때마다 순환 참조가 늘어나는 것을 끊는다 (R2-133) |
