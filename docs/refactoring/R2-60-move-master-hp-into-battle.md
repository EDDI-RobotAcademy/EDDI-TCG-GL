# [ETWGL-R2-60] 본체 체력을 전투 상태 안으로 옮긴다

선행: R2-59 │ 후행: R2-61 │ 산출물: Battle 이 양쪽 본체 체력을 들고 있다 │ Type: Rule │ Domain: Battle Master

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 본체 체력이 확인용 화면 파일 안의 값 둘로 있다
        - 0 에서 멈추는 것과 이미 쓰러진 뒤에는 피해를 안 받는 것도 그 화면이 정하고 있다
        - 재접속하면 되돌려야 하는 값인데 전투가 모른다
    - 목적
        - 본체 체력과 그 규칙을 전투 한 판 안으로 옮긴다
    - 기대 결과
        - 전투를 통째로 적으면 본체 체력도 함께 적힌다
        - 화면은 숫자를 다시 그리는 일만 한다
    - 왜 이것부터 하나
        - 원래 한 티켓이 [상대 유닛과 체력을 넘긴다] 였는데 도메인이 셋이었다
        - 본체 체력은 부르는 곳이 서른일곱이지만 값을 바꾸는 길이 둘뿐이라 가장 갈라내기 쉽다
    - 건드리지 않는 것
        - 상대 유닛의 체력과 살아 있는 순서 - 필드다. R2-61
        - 체력을 화면에 그리는 것 - 화면이다

2. 값과 함께 규칙도 옮긴다
    - 0 아래로 안 내려간다
    - 이미 쓰러졌으면 피해를 안 받는다
    - 둘 다 화면이 정할 일이 아니다

3. 화면에는 무엇을 남길지 정한다
    - 값이 바뀌었을 때 숫자를 다시 그리는 일
    - 기록을 남기는 일
    - 값이 안 바뀌었으면 아무것도 안 한다

4. 전투를 만드는 자리를 앞으로 옮긴다
    - 전투를 쓰는 함수보다 전투를 만드는 줄이 뒤에 있었다
    - 지금은 그 함수가 늦게 불려서 안 터지지만, 먼저 불리면 터진다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 본체 체력, 공격 시 감소, 카드 효과

# Issue

1. 한 티켓에 도메인이 셋 들어 있었다
    - 증상
        - [상대 유닛과 체력을 넘긴다] 한 줄인데 본체 체력, 유닛 체력, 살아 있는 순서 셋이었다
        - 부르는 곳을 세니 아흔둘이었다
    - 원인
        - 확인용 화면 안에서는 셋이 나란히 있어서 하나로 보였다
    - 처리
        - 본체와 필드로 갈랐다. 본체는 값을 바꾸는 길이 둘뿐이라 먼저 했다
        - **한 곳에 나란히 있다고 한 도메인이 아니다**

2. 규칙이 화면 쪽에 있었다
    - 증상
        - 0 에서 멈추는 것과 이미 쓰러진 뒤에는 피해를 안 받는 것이 화면 함수 안에 있었다
    - 원인
        - 값이 화면 쪽에 있으니 그 값을 지키는 규칙도 따라갔다
    - 처리
        - 값과 함께 옮겼다. 화면은 숫자를 다시 그리는 일만 남았다
        - **값을 옮길 때 그 값을 지키는 규칙도 함께 본다.** 값만 옮기면 규칙이 화면에 남는다

3. 전투를 만드는 줄이 그것을 쓰는 함수보다 뒤에 있었다
    - 증상
        - 본체 체력을 바꾸는 함수가 전투를 부르는데, 전투를 만드는 줄이 그 아래에 있었다
    - 원인
        - 값이 화면 쪽에 있을 때는 순서가 상관없었다. 전투를 거치게 하면서 순서가 생겼다
    - 처리
        - 전투를 만드는 줄을 함수 맨 앞으로 올렸다
        - **R2-51 에서 적은 [담을 그릇이 먼저 있어야 담는다] 가 또 나왔다.** 옮길 때마다 확인할 것이다
