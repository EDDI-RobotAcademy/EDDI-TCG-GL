# [ETWGL-R2-49] 전투 상태를 한 덩어리로 담을 자리를 만든다

선행: R2-24 │ 후행: R2-50 │ 산출물: Battle, BattleSnapshot, BattleRepository │ Type: Rule │ Domain: Battle

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 전투 상태가 열네 곳에 흩어져 있다. 턴, 덱, 무덤, 로스트 존, 유닛, 필드, 손패
        - 서로 모른다. 통째로 적을 방법도 통째로 되돌릴 방법도 없다
        - 재접속하면 그중 하나만 어긋나도 화면과 실제 상태가 달라진다
    - 목적
        - 열넷이 들어갈 한 덩어리를 만들고, 언제 만들고 언제 버리는지를 정한다
    - 기대 결과
        - 다음 작업부터 도메인을 하나씩 이 안으로 옮길 수 있다
    - 건드리지 않는 것
        - 열네 저장소를 옮기는 일 - 도메인마다 따로 본다. R2-50 부터 R2-56
        - 카드를 가리키는 번호를 고치는 일 - R2-57
        - 전투 밖 화면의 저장소 - 전투가 아니다

2. 흩어진 것을 옮기는 순서를 정한다
    - 도메인이 일곱이므로 티켓도 일곱으로 나눈다
    - 부르는 곳이 적은 것부터 한다. 모양이 맞는지 먼저 보고 무거운 것으로 간다
    - 턴, 덱, 무덤, 로스트 존은 앞선 작업에서 새로 만든 것이라 본편이 아직 안 쓴다
    - 무거운 것은 유닛, 필드, 손패 셋이다

3. 무엇을 담고 무엇을 담지 않을지 정한다
    - 적어 둘 수 있는 값만 담는다. 화면에 그려지는 것은 담지 않는다
    - 적어 둔 것 하나만으로 전투를 되돌릴 수 있어야 한다
    - 이 규칙을 사람이 지키는 대신 검사가 지키게 한다

4. 언제 만들고 언제 버리는지 정한다
    - 본편이 전투 화면을 준비할 때 전투 한 판이 시작된다
    - 재접속할 때는 적어 둔 것으로부터 되돌린다
    - 끝나는 자리는 아직 없다. 이 게임에 전투가 끝나는 코드가 없다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 값을 옮기지 않았고 담는 곳만 만들었으므로 아무것도 안 바뀌어야 한다
    - 전투 화면

# Issue

1. 하나였던 티켓이 도메인 일곱에 걸쳐 있었다
    - 증상
        - 열네 저장소를 한 티켓에서 옮기게 되어 있었다. 부르는 곳이 서른두 군데다
    - 원인
        - 애그리게이트가 하나라서 티켓도 하나로 잡았다
    - 처리
        - 자리를 만드는 일과 옮기는 일을 갈랐다. 옮기는 일은 도메인별로 일곱이다
        - **하나로 합쳐질 것을 만드는 일과, 거기에 넣는 일은 다른 일이다**

2. 번호를 먼저 고치는 순서가 더 비싸다
    - 증상
        - 전투 상태가 카드를 가리키는 번호는 메시를 만든 순서대로 0부터 매긴다. 화면을 새로 열면 0부터 다시 시작한다
        - 그래서 지금 번호로는 재접속 복원이 안 된다. 번호를 먼저 고쳐야 하는 것처럼 보였다
    - 원인
        - 막는 것과 비싼 것을 구분하지 않았다
    - 처리
        - 번호를 먼저 고치면 서른두 곳을 두 번 건드린다. 한 덩어리로 모은 뒤 한 곳에서 고치는 것이 싸다
        - **먼저 해야 하는 것과 먼저 하면 싼 것은 다르다**

3. 만들어만 두고 안 쓰는 규칙은 사후 승인이 된다
    - 증상
        - R2-3 에서 만든 도메인 순수성 검사가 대상 경로가 없어 그동안 통과 처리되고 있었다
    - 원인
        - 규칙이 먼저 있고 코드가 나중이라 그렇다. 이것 자체는 의도한 것이다
    - 처리
        - 이번에 폴더가 생기면서 검사가 켜졌다. 앞으로 이 폴더 안에서는 THREE, 무작위, 현재 시각이 막힌다
        - **규칙을 코드보다 먼저 두면 규칙이 코드를 따라가지 않는다**
