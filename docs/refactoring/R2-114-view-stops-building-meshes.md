# Issue

1. 다섯이 다섯 갈래가 아니었다
    - 증상
        - 다섯 군데인데 렌더러를 다섯 개 만들면 너무 잘게 나뉜다
    - 원인
        - 아이콘과 숫자는 한 덩어리다. 숫자가 아이콘 자리에 맞춰 놓여서 따로 두면 둘이 어긋난다
        - 레오닉 테두리와 확인 단추는 그 창에만 붙는다
    - 처리
        - 셋으로 묶었다. 본체 타격 영역 하나, 카드 에너지 표기 하나, 레오닉 고르기 창 하나
        - **몇 군데인지가 아니라 함께 움직이는지로 묶는다**

2. 검사로 막을 것이 THREE 자체가 아니었다
    - 증상
        - 화면이 THREE 를 가져다 쓰는 것을 막는 규칙을 걸었더니 바로 걸렸다
    - 원인
        - 화면이 좌표와 그룹과 겨냥 계산에 THREE 를 쓴다. 그것까지 막을 일이 아니다
        - 막을 것은 **메시를 만드는 것** 인데, 의존 검사는 무엇을 가져다 쓰는지만 보고 무엇을 하는지는 못 본다
    - 처리
        - 의존 검사에서 빼고 별도 검사에 넣었다. 그쪽은 코드 안의 글자를 본다
        - 일부러 어겨 보고 잡히는 것을 확인했다
        - **막을 것이 [무엇을 가져다 쓰는가] 인지 [무엇을 하는가] 인지 먼저 가른다. 검사 방법이 다르다**

3. 되돌리기에 git 을 써서 한 파일이 옛 상태로 돌아갔다
    - 증상
        - 검사가 잡히는지 보려고 넣은 줄을 지우려고 `git checkout -- <파일>` 을 썼다
        - 그 파일이 마지막으로 staged 된 상태로 돌아가면서 R2-113 과 R2-114 의 수정이 사라졌다
    - 원인
        - 서른 넘는 티켓이 커밋 안 된 상태라 되돌릴 기준점이 지금 작업이 아니었다
        - 다른 파일은 무사했다. staged 된 것이 그 파일뿐이라 그랬다
    - 처리
        - 같은 수정을 다시 넣었다. 줄 수와 세 가지 수치가 되돌아가기 전과 같은 것을 확인했다
        - **커밋 안 된 작업이 쌓여 있을 때 git 으로 되돌리지 않는다. 넣은 것을 지울 때는 넣은 방법으로 지운다**

## 창 크기를 따라가는 일이 한 자리에 모였다

본체 타격 영역은 **안 보이는 것** 이라 안 맞아도 눈에 안 띈다. 창 크기 문제가 여기서
여러 번 났다.

```
전    화면이 만든다  →  화면의 크기 조절 자리에서 다시 잰다  (잊으면 옛 자리에 남는다)
후    렌더러가 만든다 →  같은 렌더러의 resize 가 다시 잰다
```
