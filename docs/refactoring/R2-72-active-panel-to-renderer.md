선행: R2-44 │ 후행: R2-73 │ 산출물: LegacyActivePanelFrame, LegacyActivePanelRenderer │ Type: Rendering │ Domain: Battle Active Panel

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 패널과 버튼을 담아 두는 곳이 그것을 직접 만들고 화면에 붙인다
        - 그러려면 화면과 카메라가 필요한데, 혼자만 있는 것이라 처음 만든 화면에 묶인다
        - 화면이 둘이면 뒤엣것에는 안 그려진다
    - 목적
        - 만드는 일을 렌더러로 옮기고, 담아 두는 곳이 화면과 카메라를 안 들게 한다
    - 기대 결과
        - 어느 화면에서 열든 그 화면에 그려진다
    - 왜 둘을 합쳤나
        - 원래 [화면과 카메라를 안 들게] 와 [버튼을 렌더러로] 가 따로였다
        - 화면과 카메라를 드는 이유가 만들어 붙이기 때문이다. 만드는 일을 옮기면 함께 없어진다
    - 건드리지 않는 것
        - 패널의 모습 - 자리와 크기를 그대로 옮긴다
        - 확인용 화면이 쓰는 다른 패널 - 다른 모양이다

2. 보이는 모습을 지킬 기준을 세운다
    - 패널 크기, 버튼 크기, 버튼이 서는 자리가 전과 같아야 한다
    - 옮기는 일이지 고치는 일이 아니다. R2-47 에서 배운 것이다

3. 이미 있는 렌더러를 쓸 수 있는지 본다
    - 확인용 화면이 쓰는 것이 있는데 다른 모양이다
    - 그쪽은 어두운 판에 버튼을 일정한 사이로 놓는다
    - 이쪽은 흰 판에 위아래 끝을 맞춰 그 사이를 스킬 개수만큼 나눈다
    - 같아 보인다고 합치면 본편의 모습이 달라진다

4. 화면과 카메라를 누가 넘길지 정한다
    - 여는 쪽과 닫는 쪽이 자기 화면을 넘긴다
    - 담아 두는 곳은 안 든다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 액티브 패널 열기, 버튼 자리, 스킬 사용

# Issue

1. 두 티켓이 사실 한 가지 일이었다
    - 증상
        - [화면과 카메라를 안 들게] 를 먼저 하려니 할 것이 없었다
        - 그것을 드는 이유가 만들어 붙이기 때문이라, 만드는 일을 안 옮기면 못 뗀다
    - 원인
        - 겉으로 드러난 것(화면과 카메라를 든다)과 그 이유(만든다)를 따로 티켓으로 잡았다
    - 처리
        - 하나로 합쳤다
        - **드러난 것과 그 이유를 따로 잡으면 앞엣것을 먼저 못 한다**

2. 같은 이름의 렌더러가 이미 있는데 다른 모양이었다
    - 증상
        - 액티브 패널 렌더러가 이미 있었다. 그대로 쓰면 될 것 같았다
    - 원인
        - 확인용 화면이 쓰려고 따로 만든 것이다. 본편과 다른 모양으로 그린다
    - 처리
        - 옛 계산 그대로 새로 만들고, 왜 다른지 파일 맨 위에 적었다
        - **이름이 같다고 같은 것이 아니다.** 무엇을 그리는지 열어 본다

3. 창 크기가 바뀔 때 다시 안 재는 것이 있었다
    - 증상
        - 사용자가 턴 종료 버튼 주변 네온 테두리가 이상하다고 했다
    - 원인
        - 렌더러에 다시 재는 길이 있는데 부르는 곳이 없었다
        - 육각형 자리가 창 크기에서 나오므로, 안 재면 처음 크기에 남는다
    - 처리
        - 창 크기가 바뀔 때 부르게 했다. 이번 변경 때문은 아니고 원래 있던 것이다
        - **다시 재는 길을 만들었으면 부르는 곳이 있는지 본다**
