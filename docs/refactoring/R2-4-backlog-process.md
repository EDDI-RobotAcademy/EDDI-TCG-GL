# [ETWGL-R2-4] 새 작업을 시작하고 끝낼 때 무엇을 보고 판단할지 정하는 프로세스 구축

선행: R2-2 │ 후행: R2-5 │ 산출물: _TEMPLATE.md, INDEX.md, BEHAVIOR_CHECK.md, RULES.md, 노션 작업 공간

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 백로그를 쓰는 규칙과 문서는 만들었지만 실제로 어떻게 굴리는지는 정해지지 않았다
        - 새 작업을 시작할 때 번호를 어디서 받고 무엇을 복사해 시작하는지 정해진 것이 없다
        - 작업 중에 진행 상태를 어디에 적는지, 저장소와 노션 중 어디를 고치는지 정해지지 않았다
        - 완료 확인 목록을 만들어놓고 아직 한 번도 실행해보지 않았다. 실제로 돌아가는지 모른다
        - 다음에 무엇을 할지는 지금 만든 사람 머릿속에만 있다
    - 목적
        - 작업 하나가 시작해서 끝날 때까지 각 단계에서 무엇을 보고 판단하는지 정한다
        - 정한 절차를 실제로 한 번 돌려서 동작을 확인한다
    - 기대 결과
        - 새 작업을 시작할 때 누구든 같은 순서로 시작하고 형식을 매번 맞출 필요가 없다
        - 작업이 끝났는지를 사람마다 다르게 판단하지 않는다
        - 다음에 무엇을 할지 물어보지 않고 문서에서 확인한다
    - 건드리는 것
        - _TEMPLATE.md - 새 작업을 시작할 때 복사하는 틀
        - INDEX.md - 남은 작업과 순서를 보는 곳
        - BEHAVIOR_CHECK.md - 작업이 끝났는지 확인하는 곳
        - RULES.md - 백로그를 쓰다 막혔을 때 여는 곳
        - 노션 작업 공간 구성
    - 건드리지 않는 것
        - 백로그 작성 규칙 자체 - R2-2 에서 정했다. 여기서는 규칙을 쓰는 절차만 정한다
        - 네 문서의 내용 - 이름과 첫 줄만 손본다
        - R2-1~R2-3 본문 - 파일 이름과 링크만 맞춘다
        - 앞으로 생길 문서의 분류 체계 - 지금 네 건으로 일반화하기에는 표본이 적다
        - 소스 코드 - 문서와 작업 공간 작업이다

2. 새 작업을 무엇으로 시작하는지 정한다
    - 번호를 어디서 받는지 정한다
    - 무엇을 복사해서 시작하는지 정한다
    - 시작할 때 반드시 채워야 하는 것이 무엇인지 정한다
    - 노션에서 새 항목을 만들면 형식이 자동으로 채워지게 한다

3. 작업 중에 어디를 고치고 어디를 보는지 정한다
    - 저장소와 노션 중 어느 쪽이 원본인지 정한다. 양쪽에 같은 내용이 있으면 반드시 어긋난다
    - 진행 상태를 어느 쪽에서 관리하는지 정한다
    - 원본이 아닌 쪽을 언제 어떻게 맞추는지 정한다
    - 쓰다가 막혔을 때 무엇을 여는지 정한다

4. 무엇을 통과해야 끝인지 정하고 실제로 통과시켜본다
    - 완료 조건을 문서에 적고 어디서 확인하는지 정한다
    - 확인 목록을 실제로 한 번 실행해 걸리는 시간과 빠진 항목을 파악한다
    - 실행해보고 목록이 과하거나 모자라면 고친다
    - 완료 후 문제가 나왔을 때 어떻게 처리하는지 정한다

5. 다음에 무엇을 할지 고르는 방법을 정하고 게임 동작은 건드리지 않는다
    - 남은 작업과 순서를 한 곳에서 본다
    - 앞 작업이 끝나야 시작할 수 있는 것과 아닌 것을 구분한다
    - 중간에 멈춰야 할 때 어디서 멈춰도 되는지 본다
    - 문서와 작업 공간만 손대므로 게임 동작은 달라지지 않는다
