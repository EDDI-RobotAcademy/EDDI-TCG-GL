# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 카드에 붙는 것들의 저장소 이름이 전부 Repository 인데, 재접속 때 어떻게 되는지가 서로 다르다
        - 이름 하나는 실제와도 안 맞았다. Hand 가 붙어 있는데 필드 카드 자리도 담는다
    - 목적
        - R2-24 판정표대로 이름을 맞추고, 실제와 안 맞는 이름을 고친다
    - 기대 결과
        - 이름을 보면 화면을 다시 그릴 때 버려도 되는 것인지 알 수 있다
    - 이번에 하는 것
        - 다섯 개의 이름과 폴더 이름, 부르는 곳의 변수 이름을 바꾼다
    - 건드리지 않는 것
        - 네온 테두리 셋과 입력 셋 - 아직 전투 폴더 밖에 있다. 옮긴 뒤에 개명해야 두 번 안 고친다
        - 죽었다고 지정된 폴더 안의 매개변수 이름 - 확장하지 않기로 한 곳이다. 밖에 영향이 없다
        - 파일 안의 코드 - 이름과 경로만 바꾼다

2. 무엇을 무엇으로 바꿀지 정한다
    - 다시 만들 수 있는 화면 자원은 Cache, 재시작하면 초기화하는 화면 상태는 Store
    - 이름이 실제와 안 맞으면 그것도 고친다. 카드 자리 저장소에서 Hand 를 뺀다

3. 폴더를 먼저 옮기고 안을 고친다
    - 파일 이름, 클래스 이름, 부르는 곳, 변수 이름
    - 경로를 바꿀 때 어디서 부르느냐에 따라 경로 꼴이 다르다는 것에 주의한다

4. 개명 대상 밖이 안 바뀌었는지 확인한다
    - git status 로 손댈 생각이 없던 폴더가 바뀌었는지 본다
    - 형과 변수 이름이 어긋난 곳이 남았는지 본다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 손패 카드 표시와 정렬
    - 카드 상세 보기, 네온 테두리
    - 액티브 패널에서 공격과 스킬

# Issue

1. 경로 꼴이 부르는 자리마다 달라 세 번 고쳤다
    - 증상
        - 폴더 이름을 바꾼 뒤 경로를 고치는데 오류가 34개에서 10개, 그리고 0개로 세 번에 걸쳐 줄었다
    - 원인
        - 같은 폴더를 부르는데 부르는 자리에 따라 경로에 남는 부분이 다르다

```
밖에서 부를 때          ../../battle/card/scene/repository/
같은 묶음 밖에서        ../../card/scene/repository/
형제 폴더에서           ../../scene/repository/
```

    - 처리
        - 세 꼴을 다 훑어 고쳤다
        - **경로를 문자열로 바꿀 때는 부르는 자리가 몇 갈래인지 먼저 센다.** 규칙 17 의 [같은 폴더 안에서 부르면 폴더 이름이 안 나온다] 와 같은 함정인데, 형제 폴더라는 갈래가 하나 더 있었다

2. 이름에 Hand 가 있는데 필드 것도 담고 있었다
    - 증상
        - BattleFieldHandCardPositionRepository 가 손패 카드 자리만 담는 것처럼 보였다
        - 실제로는 필드에 나온 카드의 표시를 놓을 때도 이 저장소를 쓴다
    - 원인
        - 손패에서 먼저 쓰기 시작해 그 이름이 붙었고, 필드에서도 쓰게 된 뒤에 이름을 안 고쳤다
    - 처리
        - Hand 를 뺐다. BattleFieldCardPositionStore 가 되었다
        - **이름에 든 말이 실제 쓰임보다 좁으면 고친다.** 좁은 이름은 다른 데서 쓸 때 [여기 써도 되나] 를 묻게 만든다
