# [ETWGL-R2-98] 카드 정보를 화면이 아니라 전투 상태가 읽는다

선행: R2-97 │ 후행: R2-99 │ 산출물: 카드 정보를 묻는 창구 넓히기 │ Type: Rule │ Domain: Battle

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 전투 상태는 카드에 뭐가 적혀 있는지 모른다. 종류, 체력, 등급, 종족 넷만 안다
        - 공격력도 스킬 피해도 스킬 범위도 스킬 비용도 모른다
        - 그래서 화면이 카드 데이터를 직접 열어 대신 읽고, 얼마나 아픈지까지 정한다
        - 이대로 카드가 300장이 되면 [이 카드는 얼마] 가 전부 화면에 쌓인다
    - 목적
        - 카드에 적힌 값을 전투 상태가 읽을 수 있게 한다
    - 기대 결과
        - 얼마나 아픈지, 누구를 치는지, 쓸 수 있는지를 전투가 정한다
    - 건드리지 않는 것
        - 명령에서 피해량 빼기 - R2-99 다. 읽을 수 있게 된 다음이라야 뺄 수 있다
        - 카드 데이터 파일 - `src/common` 에 그대로 둔다. 닿는 길만 만든다
        - 공격력을 바꾸는 카드 여덟 장 - 아직 안 만든 카드다 (규칙 24)
        - 카드 그림 고르기 - 어느 그림 파일을 쓸지는 화면 일이다

2. 화면이 카드 데이터를 여는 곳을 전부 센다

3. 그중 무엇이 규칙 판정이고 무엇이 화면 일인지 가른다

4. 규칙은 전투로 옮기고, 카드 값은 창구로 읽게 한다
    - 카드에 적힌 값만 담는다. 계산 결과는 안 담는다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 일반 공격, 단일기, 광역기, 에너지 부족, 레오닉의 부름, 사기 전환

# Issue

1. 옮길 것이 아니라 갈라야 할 것이었다
    - 증상
        - 화면이 카드 데이터를 여는 곳이 열네 곳이었다. 다 옮기면 될 것 같았다
    - 원인
        - 열네 곳이 같은 일을 하는 것이 아니었다
    - 처리
        - 넷으로 갈랐다. 규칙 판정 셋, 중복 하나, 죽은 것 하나, 화면 일 하나
        - 규칙만 옮기고 나머지는 각각 다르게 다뤘다. 화면 일은 그대로 뒀다
        - **같은 모양으로 보이는 것도 무엇을 하는지로 갈라야 어디로 갈지 정해진다**

2. 창구가 이미 있었는데 화면이 그 옆으로 또 읽고 있었다
    - 증상
        - 화면에 카드 종족을 읽는 함수가 따로 있었다
    - 원인
        - 창구에 `getRace` 가 이미 있는데, 화면이 쓰는 자리에서는 창구를 안 거치고
          카드 데이터를 직접 열었다
    - 처리
        - 창구의 것을 쓰게 했다. 같은 뜻의 값이 두 곳에서 읽히던 것이 하나가 됐다
        - **창구를 만들어 두면 그 옆으로 새는 길이 생기는지 함께 본다**

3. 스킬 값 넷이 흩어져 있었다
    - 증상
        - 스킬 하나를 알려면 카드 데이터의 열 다섯 개를 따로 읽어야 했다
        - `스킬 1`, `스킬1 데미지`, `스킬1 언데드필요에너지`, `휴먼`, `트런트`
    - 원인
        - 카드 데이터가 표에서 나온 것이라 열이 평평하게 늘어서 있다
    - 처리
        - 창구에서 스킬 하나를 [누구를 치는가 / 얼마 / 종족별 비용] 한 덩이로 돌려준다
        - 읽는 쪽은 열 이름을 몰라도 된다. 한글 열 이름과 `as any` 가 창구 안에만 남는다
        - **표에서 나온 평평한 값은 창구에서 한 덩이로 묶어 넘긴다**

## 지금은 그대로 쓰지만 나중에 달라지는 것

창구가 돌려주는 피해는 **카드에 적힌 기본값** 이다. 지금은 그 값이 그대로 답이라
전투도 그대로 쓴다. 붙은 것이 생기면 전투가 이 값에서 시작해 계산하게 되고, 창구는
바뀌지 않는다. 최종값을 어디에 저장하지 않는다는 것도 코드에 적어 뒀다 (규칙 23).
