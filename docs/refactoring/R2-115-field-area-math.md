# Issue

1. 제목이 가리키던 문제가 실제 문제가 아니었다
    - 증상
        - 제목이 [필드 영역이 그림을 들지 않게] 였는데, 필드 영역 프레임 넷은 이미 그림을 안 든다
    - 원인
        - 백로그를 쓸 때 짐작으로 적었다. 코드를 열어 보니 다른 문제였다
        - 실제 문제는 필드 영역이 자기 크기를 낼 줄 몰라서 화면이 대신 계산하는 것이다
    - 처리
        - 제목을 실제 문제로 바꿨다
        - **티켓을 시작할 때 제목이 가리키는 것이 실제로 그런지 먼저 본다. 짐작으로 적힌 제목이 있다**

2. 상대 필드 쪽 함수가 아예 없었다
    - 증상
        - 내 필드에는 자리를 내는 함수가 있는데 상대 필드에는 없다
        - 화면 주석에 [내 필드 것과 같은 식] 이라고 적고 손으로 베껴 적어 두었다
    - 원인
        - 내 필드 쪽에 먼저 필요해서 그때 만들고, 상대 필드 쪽은 필요할 때 화면에서 해결했다
    - 처리
        - 셈하는 식을 함께 쓰는 자리로 빼고 양쪽에 함수를 두었다
        - **주석에 [저기와 같은 식] 이라고 적을 일이 생기면 그것이 옮길 자리라는 뜻이다**

3. 프레임 둘을 합치고 싶어졌다
    - 증상
        - 내 필드와 상대 필드 프레임이 칸도 같고 값도 둘만 다르다
    - 원인
        - 생김새가 같다
    - 처리
        - 안 합쳤다. 셈하는 식만 함께 쓰고 프레임은 둘로 두었다
        - 두 값은 다른 이유로 바뀐다. 내 필드는 손패 줄 수에 맞춰 움직이고, 상대 필드는 상대가
          내는 것에 맞춰 움직인다. 합쳤으면 한쪽을 고칠 때 다른 쪽이 따라 움직인다 (R2-7)
        - **함께 쓸 것은 값이 아니라 식이다**

4. 확인하다가 전부터 있던 것이 나왔다 — 본체 체력 숫자가 되돌아간다
    - 증상
        - 네더 블레이드 단일기 중에 파멸의 계약을 쓰면 계약의 피해만 보인다
        - 값은 맞다. 다음 턴에 단일기를 쓰면 정상으로 보인다
    - 원인
        - 연출 둘이 겹치면 각자 자기가 들고 있던 값으로 그린다
        - 뒤늦게 도착한 쪽이 더 오래된 값을 들고 있으면 숫자가 되돌아간다
        - 체력 숫자는 그림이라 갈아 끼우는 데 시간이 걸린다. 그 사이에 끼어드는 경우도 있었다
    - 처리
        - 내려가는 쪽만 그리게 막았다. 본체 체력은 줄기만 한다
        - 그림을 읽는 사이에 더 낮은 값이 들어왔으면 다 읽은 옛 그림을 안 붙이고 버린다
        - 부르는 자리가 다섯이라 화면이 아니라 렌더러에 넣었다
        - **같은 종류가 세 번째다 (R2-100 화면 흔들림, R2-112 확인 중 에너지 숫자, 이번 본체 체력).
          부르는 자리가 여럿이면 화면마다 막지 않고 그리는 쪽에 한 번 막는다**
        - 이번에는 남은 것을 그 자리에서 다 훑었다. 둘이 더 있었다
          · 사기 전환의 필드 에너지 숫자 — 알갱이마다 올려 보이는데 도는 중에 다른 데서 바뀌면 어긋난다
          · 에너지 번의 상대 유닛 에너지 — 같은 유닛에 두 번 빠르게 쓰면 겹친다
        - 필드 에너지는 오르내려서 한쪽만 그리는 방법을 못 쓴다. 끝나고 참인 값으로 맞췄다
        - **규칙 28 로 적었다. 값이 한쪽으로만 움직이면 그 쪽만 그리고, 오르내리면 끝나고 참인 값으로 맞춘다**

## 왜 이게 창 크기 문제의 뿌리였나

같은 식이 여덟 군데 있으면 **하나를 고칠 때 나머지를 잊는다.**

R2-87 부터 R2-93 까지 여덟 티켓이 그 종류였고, 그중 다섯을 사용자가 찾았다. 안 보이는
것이라 눈에 안 띄어서다.

```
전    화면이 여덟 군데에서 곱한다  →  하나를 고치면 일곱이 남는다
후    한 자리에서 낸다            →  고칠 곳이 하나다
```
