# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 이름이 Repository 인데 담는 것은 패널 메시와 버튼 메시다. 다시 만들 수 있는 화면 자원이다
        - 그런데 그것만 담지 않는다. 어느 버튼이 눌렸는지도 담고, 화면과 카메라도 들고 있고, 버튼을 만들기까지 한다
    - 목적
        - 담는 것의 주된 성격에 이름을 맞춘다
    - 기대 결과
        - 이름을 보면 화면을 다시 그릴 때 버려도 되는 것임을 알 수 있다
    - 이번에 하는 것
        - 이름과 폴더 이름, 부르는 곳의 변수 이름을 바꾼다
    - 건드리지 않는 것
        - 어느 버튼이 눌렸는지를 갈라내는 일 - 화면 상태다. 별도 작업
        - 화면과 카메라를 저장소에서 빼내는 일 - 싱글턴이라 초기화 순서에 기댄다. 별도 작업
        - 버튼을 만드는 일 - 렌더러가 할 일이다. 별도 작업
        - 셋 다 동작이 달라질 수 있어 개명과 섞으면 원인을 가릴 수 없다

2. 무엇을 담는지 확인한다
    - 파일을 열어 담는 값을 본다
    - 밖에서 무엇을 부르는지 세어 어느 쪽이 주된 쓰임인지 본다

3. 폴더를 먼저 옮기고 안을 고친다
    - 경로를 바꿀 때 폴더 전체 경로를 붙여 경계를 맞춘다
    - 형과 변수 이름의 짝을 맞춘다

4. 개명 대상 밖이 안 바뀌었는지 확인한다
    - git status 로 손댈 생각이 없던 폴더가 바뀌었는지 본다
    - 옛 이름이 한 곳도 안 남았는지 확인한다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 필드 카드를 클릭해 액티브 패널이 열리는지
    - 공격, 스킬1, 스킬2 버튼이 눌리는지
    - 다른 곳을 클릭하면 패널이 닫히는지

        - 생성자가 camera 와 scene 을 받는다. 싱글턴이라 처음 만든 화면에 묶인다
