# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 필드 저장소 열 개의 이름이 전부 Repository 인데 성격이 셋으로 갈린다
        - 재접속하면 복원되어야 하는 것, 화면을 다시 그리면 되는 것, 지워도 다시 만들 수 있는 것이 섞여 있다
        - 새 데이터가 생겼을 때 어디에 둘지 이름만 보고는 알 수 없다
    - 목적
        - R2-24 판정표대로 이름을 맞춘다
    - 기대 결과
        - 이름을 보면 재접속 때 어떻게 되는 것인지 알 수 있다
    - 이번에 하는 것
        - 여섯 개의 이름을 바꾼다. 하는 일은 그대로다
    - 건드리지 않는 것
        - 흡수 대상 넷 - 내 필드와 상대 필드에 놓인 카드, 칸 배치. R2-33 에서 전투 안으로 들어가며 사라진다
        - 상대 속성 표시 셋과 내 필드 클릭 판정 - 아직 전투 폴더 밖에 있다. R2-52 에서 옮긴 뒤에 개명해야 두 번 안 고친다
        - 파일 안의 코드 - 이름과 경로만 바꾼다

2. 무엇을 무엇으로 바꿀지 정한다
    - 다시 만들 수 있는 화면 자원은 Cache 로 끝낸다
    - 재시작하면 초기화하는 화면 상태는 Store 로 끝낸다
    - 폴더 이름도 함께 바꾼다. repository 폴더에 Cache 가 들어 있으면 헷갈린다

3. 이름과 경로를 바꾼다
    - 파일 이름, 인터페이스 이름, 클래스 이름, 부르는 모든 곳
    - 경로를 바꿀 때 폴더 이름의 경계를 맞춘다

4. 개명 대상 밖이 안 바뀌었는지 확인한다
    - 타입 검사는 경로가 맞기만 하면 통과한다. 엉뚱한 폴더가 일관되게 바뀌면 오류가 나지 않는다
    - git status 로 손댈 생각이 없던 폴더가 바뀌었는지 본다
    - 옛 이름이 한 곳도 안 남았는지 확인한다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 손패에서 카드를 내 필드로 끌어다 놓기
    - 필드 카드를 클릭해 액티브 패널 열기
    - 필드 카드에 네온 테두리가 켜지는지
    - 카드를 여러 장 놓고 정렬되는지
    - 상대 필드에 카드가 그려지는지

    - 처리
