# Issue

1. R2-111 에서 못 뺀 이유가 [정할 수 없다] 였는데 세어 보니 정해졌다
    - 증상

    - 원인
        - 그때는 세어 보지 않고 짐작으로 적었다
    - 처리
        - 연출 부르는 함수마다 바깥에서 무엇을 쓰는지 세었다. 둘에서 열하나, 합쳐 열다섯이었다
        - **[정할 수 없다] 와 [안 세어 봤다] 는 다르다. 세어 보면 정해지는 것이 있다**

2. 연출을 만드는 데 필요한 것이 카드마다 달랐다
    - 증상
        - 죽음의 낫은 장면만 받는데 파멸의 계약은 그리는 기계와 카메라와 그리는 방법을 가로채는 것까지 받는다
    - 원인
        - 연출마다 하는 일이 다르다. 화면을 찍어 일그러뜨리는 연출은 그리는 과정에 끼어든다
    - 처리
        - 카드는 [무엇을] 만들지만 말하고 만드는 일은 창구가 한다. 장비는 창구가 안다
        - **카드 파일이 화면의 장비를 알면 안 된다. 만드는 일을 창구에 맡긴다**

3. 연출을 새로 만들면 창 크기를 따라가는 등록이 빠졌다
    - 증상
        - 옛 코드는 연출 객체를 미리 만들어 크기 조절 목록에 넣어 뒀다 (R2-90 에서 고친 자리)
        - 카드 파일에서 쓸 때마다 새로 만들면 그 목록에 안 들어간다
    - 처리
        - 이미 있던 [도는 동안만 담아 두는 것] 을 창구에 넣고 감싸서 돌리게 했다
        - 칸에 [연출을 돌릴 때는 이것으로 감싼다. 안 감싸면 도는 중에 창을 바꿀 때 어긋난다] 고 적었다
        - **옮기기 전에 옛 코드가 왜 그렇게 되어 있었는지 본다. 고쳐 둔 이유가 있다**

4. 지운 갈림길이 새 길로 안 들어오는 것을 세 번 놓쳤다
    - 증상
        - 첫째 — 죽음의 대지 갈림길을 지울 때 조건문만 없애서 몸통이 앞 카드 뒤에 무조건 붙었다
        - 둘째 — 사기 전환 갈림길을 지울 때 시체 폭발 갈림길까지 딸려 지워졌다
        - 셋째 — 라우팅을 ITEM 안에만 넣어서 ENERGY 와 SUPPORT 카드가 아무 데도 안 걸렸다
    - 원인
        - `} else if (...) {` 은 여닫는 괄호가 하나씩이라 괄호 깊이로는 끝을 못 찾는다
        - 셋 다 타입 검사와 빌드를 통과한다. 갈림길 하나가 사라지는 것은 문법이 안 깨진다
    - 처리
        - 끝을 찾는 방법을 [들여쓰기가 같은 다음 닫는 괄호] 로 바꿨다
        - 셋째는 사용자가 찾았다. 지운 뒤 부르는 곳 수는 세었는데 **새 길로 들어오는지** 는 안 셌다
        - **갈림길을 옮기면 [옛 길이 없어졌는가] 와 [새 길로 들어오는가] 를 둘 다 센다**
