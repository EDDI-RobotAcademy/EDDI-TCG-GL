# [ETWGL-R2-55] 카드가 누구인지와 몇 번째인지를 갈라낸다

선행: R2-54 │ 후행: R2-56 │ 산출물: 화면 카드 저장소와 손패 저장소가 구멍을 남기지 않는다 │ Type: Rule │ Domain: Battle Card

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 화면 카드를 담는 열쇠가 [만들 때 몇 개 있었나] 였다. 신원이면서 동시에 자리다
        - 그래서 중간 카드를 지우면 뒤엣것의 자리가 밀리고, 다음에 만드는 카드가 이미 쓰던 번호를 받는다
        - 그것을 막으려고 지운 자리에 빈 것을 도로 넣었다. 손패도 같은 자리에 묘비를 남겼다
        - 손패에서 필드로 갈 때 [손패에서 몇 번째인가] 를 세어 그 수로 화면 카드를 꺼냈다. 두 곳이 나란히 구멍을 남겨야만 맞는 방식이다
    - 목적
        - 카드가 누구인지와 필드에서 몇 번째인지를 다른 값으로 만든다
    - 기대 결과
        - 빈 자리와 묘비가 없어진다. 지우면 그냥 없다
        - 필드와 손패를 전투 상태로 옮길 때 이 방식을 그대로 들여오지 않는다
    - 왜 순서를 바꿨나
        - 원래 이 일이 필드와 손패를 옮긴 뒤였다
        - 카드를 주고받는 방식 자체가 번호에 매여 있어서, 놔둔 채 옮기면 빈 자리를 전투 상태 안으로 들여온다
    - 건드리지 않는 것
        - 필드와 손패를 전투 상태로 옮기는 일 - R2-56, R2-57
        - 상대 필드 배치가 쓰는 묘비 - 그 도메인을 옮길 때 함께 본다

2. 신원과 자리를 무엇으로 할지 정한다
    - 신원은 카드가 누구인가다. 전투 내내 안 바뀐다. 줄 세우는 데 쓰지 않는다
    - 자리는 목록에서 몇 번째인가다. 들고 나면서 바뀐다. 목록이 들고 있다
    - 새로 들어오는 것은 맨 뒤다. 부활도 새로 나오는 것과 같다
    - 필드가 13, 20, 33 일 때 17 이 부활하면 13, 20, 33, 17 이다

3. 왜 신원으로 줄을 세우면 안 되는지 확인한다
    - 20 번이 죽었다가 부활하고 필드에 30 번이 있으면, 번호순으로는 20 이 앞에 온다
    - 나중에 들어온 것이 앞으로 끼어든다. 자리가 번호에 매여 있으면 반드시 생긴다
    - 그래서 목록이 순서를 따로 들고 있어야 한다

4. 두 저장소를 함께 바꾼다
    - 한쪽만 고치면 그 순간 어긋나 엉뚱한 카드가 필드로 나간다
    - 화면 카드 저장소의 열쇠를 카드 자신의 번호로 바꾸고 빈 자리를 없앤다
    - 손패 저장소가 진짜로 지우게 한다
    - 손패에서 필드로 갈 때 카드 번호로 바로 꺼낸다
    - 화면 카드 번호를 필드 카드 번호 자리에 넣던 네 곳을 바로잡는다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 손패에서 필드로 내보내기. 여러 장 연달아, 가운데 것도
    - 손패 정렬, 페이지 넘기기
    - 필드 카드 누르기, 일반 공격, 스킬

# Issue

1. 신원과 자리를 한 값으로 쓰고 있었다
    - 증상
        - 화면 카드를 담는 열쇠가 만들 때의 개수였다. 그 값이 누구인지도 되고 몇 번째인지도 됐다
    - 원인
        - 담는 곳을 만들 때 순서대로 넣기만 하면 되던 시절의 방식이 남았다
    - 처리
        - 열쇠를 카드 자신의 번호로 바꿨다. 자리는 목록이 들고 있게 했다
        - **한 값이 두 가지를 뜻하면 하나를 바꿀 때 다른 하나가 따라 바뀐다**

2. 신원으로 줄을 세우자는 첫 제안이 틀렸다
    - 증상
        - 처음에 [카드마다 안 바뀌는 번호 하나를 주고 그 번호들의 목록으로 만든다] 고 제안했다
        - 사용자가 부활을 짚었다. 20 번이 부활하면 30 번보다 앞에 온다
    - 원인
        - 신원을 하나로 만드는 것과 그 신원으로 줄을 세우는 것을 갈라 말하지 않았다
    - 처리
        - 신원은 줄 세우는 데 쓰지 않는다고 못 박았다. 자리는 목록이 따로 든다
        - **하나로 합칠 때는 무엇까지 합치는지를 함께 말해야 한다.** 안 그러면 듣는 쪽이 더 넓게 읽는다

3. 두 곳이 서로의 구멍에 기대고 있었다
    - 증상
        - 손패는 묘비를, 화면 저장소는 빈 자리를 남겼다. 둘 다 지우지 않아서 자리가 나란히 유지됐다
    - 원인
        - 손패에서 필드로 갈 때 [손패에서 몇 번째인가] 로 화면 카드를 꺼냈다. 두 곳의 자리가 같아야만 맞는다
    - 처리
        - 한 번에 함께 바꿨다. 한쪽만 고치면 그 순간 엉뚱한 카드가 나간다
        - **틀린 것 둘이 서로를 받치고 있으면 하나만 고치는 것이 아무것도 안 고치는 것보다 나쁘다**

4. 우연히 맞는 것이 세 겹이었다
    - 증상
        - 화면 카드 자신의 번호와 담는 열쇠, 손패에서의 차례, 필드 카드 자신의 번호가 서로 다른 값인데 다 맞아떨어졌다
    - 원인
        - 번호를 세는 곳이 각자 0 부터 시작해서, 하나 만들 때마다 나란히 올라갔다
    - 처리
        - 열쇠와 찾는 길을 신원 하나로 모았다
        - **각자 0 부터 세면 처음에는 늘 맞는다.** 맞는 것과 맞게 만든 것은 다르다
