# Issue

1. 계획표에 적힌 근거가 사실이 아니었다
    - 증상
        - 계획표에 [속성 마크를 유닛에 넣은 이유는 필드에 나온 카드의 상태를 표시하는 것이기 때문이다. 손패 카드에는 속성 마크가 붙지 않는다] 고 적혀 있었다
        - 실제로는 손패 카드에도 붙는다. 상태 값에 HAND 가 있고, 손패 전용 관리자가 따로 있고, 손패 서비스가 부른다
    - 원인
        - 계획을 세울 때 폴더 이름과 짐작으로 근거를 적었다. 코드를 열어 확인하지 않았다
    - 처리
        - 속성 표시 여섯 폴더를 유닛에서 빼고 R2-34, R2-33 로 옮겼다
        - 계획표의 그 문장을 고쳤다
        - **문서에 적힌 근거도 착수 전에 확인한다.** 적혀 있다고 확인된 것이 아니다

2. 경로를 대조할 때 확장자를 빼먹었다
    - 증상
        - 옮긴 뒤 타입 오류 56건이 났다. 밖에서 부르는 곳이 하나도 안 고쳐졌다
    - 원인
        - import 에 적힌 경로는 확장자가 없고, 옮긴 파일 목록은 .ts 가 붙어 있다. 둘을 그대로 맞대어 보니 하나도 안 맞았다
        - R2-20 에서 만든 도구에는 이 처리가 있었는데 이번에 옮겨 적으면서 빠뜨렸다
    - 처리
        - 대조할 때 .ts 를 붙여 다시 훑었다
        - **도구를 옮겨 적을 때가 처음 만들 때보다 위험하다.** 왜 그 줄이 있었는지를 모르고 지운다

3. 유닛이 들고 있는 세 가지가 빈 껍데기다
    - 증상
        - AttachedEnergyInfo, ExtraUsefulEffectInfo, HarmfulEffectInfo 세 클래스가 안이 비어 있다
        - 암흑 화염과 빙결 같은 해로운 효과가 들어갈 자리인데, 지금은 시나리오 파일 안 Set 에 들어 있다
    - 원인
        - 자리만 만들어 두고 채우지 않았다
    - 처리
        - 옮기기 티켓이라 채우지 않았다
        - R2-49 에서 전투 상태를 한 단위로 묶을 때 함께 본다
        - **전투 상태가 시나리오 파일 안에 있으면 재접속 때 사라진다.** 필드 에너지 수가 화면 글자에 있던 것과 같은 종류다
