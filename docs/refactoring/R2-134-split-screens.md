# Issue

1. 순환 참조가 쪼개기를 막고 있던 벽이었다
    - 증상
        - 화면마다 저만 쓰는 것이 0파일이었다. 쪼갤 덩이가 아예 없었다
    - 원인
        - 화면이 길 안내를 통째로 받고, 길 안내가 길 목록을, 길 목록이 화면 다섯을 들여왔다
        - 화면 하나를 건드리면 다섯이 다 딸려온다
    - 처리
        - 화면이 쓰는 것이 `navigate` 하나뿐임을 세고, 그 창구만 받게 했다
        - **처음에 이 티켓을 [순환 참조 경고가 늘어난다] 로 세웠다. 증상이었다.** 경고 개수를 세는 것으로 끝내면 값을 못 찾는다. 재 보니 그 고리가 첫 로딩 6.87MB 의 원인이었다

2. 쪼개면 응답성이 나빠진다
    - 증상
        - 화면별로 쪼개면 첫 화면은 빨라지지만, 각 화면을 처음 누를 때 받아 오는 기다림이 생긴다
    - 원인
        - 비용이 없어진 것이 아니라 뒤로 옮겨졌을 뿐이다. 로딩은 한 번이지만 멈칫은 매번 눈에 띈다
    - 처리
        - 로비가 뜬 뒤 브라우저가 한가한 틈에 나머지 넷을 미리 받아 둔다. 누를 때는 이미 와 있다
        - **비용을 옮기는 것과 없애는 것은 다르다.** 옮기기만 하면 한쪽 숫자는 좋아지고 사용자 느낌은 나빠진다

3. 음악이 돌아올 때 다시 걸리지 않았다 — 사용자가 찾았다
    - 증상
        - 상점에 갔다 로비로 돌아오면 로비 음악이 안 나온다
    - 원인
        - 화면이 **만들어질 때** 음악을 걸었다. 화면은 한 번만 만들어진다
        - 돌아올 때는 만들기가 다시 안 되므로 걸지도 틀지도 않는다
        - 브라우저가 첫 누름 전에는 소리를 막으므로, 화면마다 [첫 누름 한 번을 기다리는] 처리기를 따로 두고 있었다. 한 번 쓰이면 사라져서 돌아올 때 쓸 것이 없었다
    - 처리
        - **보여질 때** 걸게 옮겼다. 첫 누름을 기다리는 일은 소리 담당 한 곳으로 모았다
        - **한 번만 하는 것과 보여질 때마다 하는 것을 가른다.** 차리는 일은 한 번이고 음악은 매번이다. 둘을 같은 자리에 두면 돌아올 때 빠진다

## 고리를 끊은 방법

```
전:  화면 → 길 안내 → 길 목록 → 화면 다섯
후:  화면 → [옮겨 달라] 창구      (끝)
     길 안내 → 길 하나의 모양
     길 목록 → 부를 때 받아 오는 화면
```

화면이 길 안내에서 쓰는 것이 `navigate` 하나뿐이었다. 통째로 받을 이유가 없었다.
