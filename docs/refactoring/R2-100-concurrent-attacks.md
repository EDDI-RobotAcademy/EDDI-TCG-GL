# [ETWGL-R2-100] 앞 공격이 끝나기 전에도 다음 공격을 할 수 있게 한다

선행: R2-99 │ 후행: R2-101 │ 산출물: 겹쳐 도는 공격 연출 │ Type: Rule │ Domain: Battle Unit

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 공격 연출이 도는 중에 다른 유닛으로 또 공격하면 연출이 안 돈다
        - 그런데 피해는 이미 들어간 뒤다. 명령을 먼저 보내고 연출을 그 다음에 부르기 때문이다
        - **사용자가 못 본 사이에 값이 바뀐다**
        - 턴 시간이 빠듯해 사용자는 연달아 공격해야 한다. 막으면 시간을 잃는다
    - 목적
        - 공격 연출이 겹쳐 돌게 한다
    - 기대 결과
        - 빠르게 연달아 눌러도 연출이 다 돌고, 본 대로 값이 바뀐다
    - 건드리지 않는 것
        - 명령을 보내는 순서 - 값은 지금처럼 연출을 기다리기 전에 다 바꾼다
        - 연출이 어떻게 생겼는지 - 겹쳐 돌 때 깨지는 것만 고친다

2. 왜 조용히 건너뛰는지 찾는다

3. 막을지 겹쳐 돌게 할지 정한다

4. 겹쳐 돌 때 깨지는 데를 찾아 고친다
    - 두 연출이 같은 것을 건드리는 자리가 있다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 빠르게 연달아 공격, 일반 공격, 단일기, 광역기, 본체 공격

# Issue

1. 처음에 막는 쪽으로 고쳤다가 되돌렸다
    - 증상
        - 앞 공격이 끝날 때까지 다음 공격을 막고 안내 문구를 띄우게 했다
    - 원인
        - [사용자가 못 본 사이에 값이 바뀐다] 는 것만 보고 막는 것으로 풀었다
        - 턴 시간이 빠듯하다는 것을 안 봤다. 막으면 사용자가 시간을 잃는다
    - 처리
        - 막는 것을 걷어내고 겹쳐 돌게 했다
        - **안전하게 만드는 방법이 여럿이면, 사용자가 무엇을 잃는지로 고른다**

2. 조용히 건너뛰는 코드가 문제를 가리고 있었다
    - 증상
        - 연출만 안 도는 것으로 보였다. 얼핏 연출 문제다
    - 원인
        - 연출 쪽에 [도는 중이면 그냥 돌아간다] 가 있었다
        - 화면은 명령을 먼저 보내므로, 돌아갈 때 피해는 이미 들어가 있었다
    - 처리
        - 그 줄을 없앴다. 이제 겹쳐 돈다
        - **조용히 넘어가는 코드는 무엇이 안 일어났는지를 감춘다**

3. 겹쳐 돌게 하니 화면 흔들기가 뚝 끊긴다
    - 증상
        - 두 공격이 같이 흔드는데, 먼저 끝난 쪽이 화면을 제자리로 돌려 버린다
    - 원인
        - 흔들기가 끝날 때 무조건 제자리로 돌렸다. 하나만 돈다고 보고 쓴 코드다
    - 처리
        - 지금 몇 개가 흔드는지 세고, 마지막 하나가 끝날 때만 돌린다
        - 연출이 끝나며 제자리로 돌리는 세 곳도 같은 것을 거치게 했다
        - **하나만 돈다고 보고 쓴 코드는 겹치는 순간 서로를 되돌린다**

## 알면서 안 고친 것

연출은 시작할 때 창 크기를 한 번 재고 그 값으로 끝까지 그린다. 그리는 것을 담는 겹도
처음 담길 때 창 크기를 적어 둔다.

그래서 **연출 둘 사이에 창 크기가 바뀌면** 뒤 연출의 그림이 앞 연출 기준으로 늘어난다.
공격 하나가 도는 동안 창을 바꾸고, 끝나기 전에 또 공격해야 나오는 경우다.

지금 고치려면 연출이 돌 때마다 겹을 따로 만들어야 하는데, 실제로 그 경우를 본 적이
없다. 규칙 24 대로 보이면 그때 고친다.
