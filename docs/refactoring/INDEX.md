## 왜 이 작업을 하는가 (한 문단 요약)

카드 데이터 100장 중 개별 구현이 필요한 것이 97장인데 **12장만 완료**되었다.
남은 85장을 현재 구조로 진행하면 시나리오 파일이 16,000~28,000라인이 된다
(현재 3,838라인, 카드 1장당 170~500라인이며 증가 추세).
**카드당 비용을 "증가"에서 "상수"로 바꾸는 것**이 이 리팩토링의 목표다.

## 의존 순서

```
R2-1  의존성 검사
  │     ★ 나머지 8개의 검증 수단. 반드시 먼저.
  ▼
R2-2  battle 컨텍스트 분리
  ▼
R2-3  저장소 책임 분류
  ▼
R2-4  Battle 애그리게이트
  │
  ├──▶ R2-5  식별자 통합 ──▶ R2-6  처리 순서 분리 ──▶ R2-7  카드 능력 정의
  │        (영속성 전제)         (85장 계약 확정)         (85장 착수 가능)
  │
  ├──▶ R2-8  TurnSystem          독립. 필요할 때
  └──▶ R2-9  HUD 렌더러 정리     독립. 필요할 때
```

**R2-1 → R2-7이 임계 경로다.** R2-8 · R2-9는 R2-4 이후 언제든 가능하며,
해당 영역을 손볼 때 수행한다.

## 중단해도 되는 지점

리팩토링을 도중에 멈춰야 한다면 아래가 안전한 정지점이다.

| 정지점 | 상태 |
|---|---|
| R2-3 완료 후 | 구조는 정리됨. 카드 추가 비용은 그대로 |
| **R2-6 완료 후** | **체감 개선의 대부분 확보.** 85장을 시작해도 됨 |
| R2-7 완료 후 | 카드당 비용이 상수로 수렴 |
