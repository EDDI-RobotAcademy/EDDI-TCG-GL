# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 손패로 판정된 저장소 넷 중 하나만 개명 대상인데, 그 하나의 판정도 틀려 있었다
        - R2-24 표에 [페이지 넘김 버튼 메시] 라고 적었는데 실제로 담는 것은 페이지 번호뿐이다
    - 목적
        - 이름을 담는 것에 맞춘다
    - 기대 결과
        - 이름을 보면 재시작 때 초기화되는 값이라는 것을 알 수 있다
    - 이번에 하는 것
        - 이름과 폴더 이름, 부르는 곳의 변수 이름까지 바꾼다
    - 건드리지 않는 것
        - 손패에 든 카드와 카드 번호 목록 - 재접속하면 복원되어야 한다. R2-33 에서 전투 안으로 들어간다
        - 손패 클릭 판정 - 아직 전투 폴더 밖에 있다. 담는 것도 없어 저장소가 아니다
        - 버튼을 만드는 두 함수 - 저장소가 만들 일이 아니다. 동작이 달라질 수 있어 별도 작업으로 뺀다

2. 무엇을 담는지 다시 확인한다
    - 표에 적힌 것을 믿지 않고 파일을 연다
    - 밖에서 무엇을 부르는지 세어 실제 쓰임을 본다

3. 폴더를 먼저 옮기고 안을 고친다
    - 반대로 하면 경로에 옛 폴더 이름이 남아 두 번 훑게 된다
    - 경로를 바꿀 때 폴더 전체 경로를 붙여 경계를 맞춘다

4. 형과 변수 이름의 짝을 맞춘다
    - 형은 Store 인데 변수가 Repository 면 다음 사람이 어느 쪽을 믿을지 헷갈린다
    - R2-26 이 남긴 여섯 개도 함께 맞춘다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 손패가 여러 장일 때 페이지를 넘기는 것을 확인한다
    - 키보드로 페이지를 넘기는 것도 확인한다

# Issue

1. R2-24 판정표가 틀려 있었다
    - 증상
        - 표에 [페이지 넘김 버튼 메시] 라고 적혀 있어 Cache 로 분류했다
        - 파일을 여니 담는 것은 페이지 번호와 한 페이지에 몇 장인지뿐이었다
        - 버튼은 만들어서 돌려주고 담지 않는다
    - 원인
        - R2-24 에서 43개를 판정할 때 이 파일은 메서드 이름만 보고 넘겼다
        - createPrevButton 이 있으니 버튼을 담는 줄 알았다
    - 처리
        - Cache 가 아니라 Store 로 바꿨다
        - **판정표도 착수할 때 다시 확인한다.** 표는 판정한 사람이 본 만큼만 맞다

2. 저장소가 메시를 만들고 있다
    - 증상
        - createPrevButton, createNextButton 이 THREE.Mesh 를 만들어 돌려준다
        - 바로 옆에 HandPageButtonsRendererV2 가 있는데 저장소가 따로 만든다
    - 원인
        - 렌더러를 만들면서 옛 코드를 지우지 않았다
    - 처리
        - 이번 범위 밖으로 두었다. 빼내는 것은 동작이 달라질 수 있는 일이라 개명 티켓과 섞으면 원인을 가릴 수 없다
        - **CLAUDE.md 의 [Renderer 가 THREE.Object3D 를 만드는 유일한 곳] 에 어긋난다.** 별도 작업으로 등록한다
