# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 메시를 담아 둔 곳이 비울 때 지도에서 빼기만 한다. 그래픽 카드에 올라간 것은 그대로 남는다
        - 자바스크립트 객체는 참조가 끊기면 알아서 치워지지만, 그래픽 카드에 올린 것은 놓아 달라고 말해야 놓아준다
        - 전투 저장소 43개 중 놓아주는 것은 액티브 패널 하나뿐이다
    - 목적
        - 무엇을 언제 놓아주고 무엇을 두고 갈지 한 곳에 적어 둔다
    - 기대 결과
        - 새 메시를 담는 곳을 만들 때 이 약속을 붙이면 된다
    - 이번에 하는 것
        - 약속을 만들고 카드 메시를 담는 다섯 곳에 붙인다. 아무도 부르지 않는다
    - 건드리지 않는 것
        - 실제로 부르는 일 - 지금 안 버리던 것을 버리기 시작하면 아직 쓰고 있는 것을 버릴 수 있다. R2-45
        - 전투 중에 만들어 쓰는 글자 그림 - 이건 실제로 쌓이지만 다른 문제다. R2-46
        - 덱 편성 화면의 저장소 29개 - 이미 다른 방식을 쓰고 있다. 전투가 끝난 뒤 본다

2. 언제 놓아주는지 정한다
    - 카드가 화면에서 빠질 때 - 필드에 있던 카드가 무덤이나 로스트존으로 간다
    - 화면 크기가 바뀔 때 - 크기에 맞춰 다시 만들면서 옛것을 놓아준다
    - 전투가 끝날 때 - 전부 새로 만든다
    - 셋 중 첫째가 가장 자주 일어난다. 카드 한 장이 무덤에 갈 때마다 생긴다

3. 무엇을 놓아주고 무엇을 두고 갈지 정한다
    - 놓아준다 - geometry, material. 이 메시만 쓰는 것이다
    - 두고 간다 - 카드 그림. TextureManager 가 한 장을 여러 카드에 나눠 준다
    - 19번 카드가 필드에 둘 있으면 그림 하나를 둘이 쓴다. 한 장이 무덤에 갈 때 놓아주면 남은 한 장이 깨진다
    - 그림은 한 번만 읽고 다시 읽지 않으므로 전투를 여러 번 해도 늘지 않는다. 놓아줄 이유가 없다

4. 화면을 모르고도 놓아줄 수 있게 한다
    - 메시를 담는 곳이 화면을 들고 있으면, 싱글턴이라 어느 화면이 먼저 만들었는지에 따라 다른 화면에 묶인다
    - 카드 메시는 화면에 바로 붙지 않고 묶음 안에 들어간다. 화면에 빼 달라고 하면 직계 자식이 아니라서 아무 일도 일어나지 않는다. 오류도 나지 않는다
    - 그래서 메시가 자기 부모에게 빼 달라고 한다

5. 다섯 곳에 붙인다
    - 카드 메시를 담는 곳 셋, 속성 표시 메시를 담는 곳 둘
    - 붙이되 부르지 않는다

6. 게임 동작이 달라지지 않는다
    - 기존 메서드의 본문을 하나도 바꾸지 않았다
    - 새로 만든 것은 아무도 부르지 않는다
    - 타입 검사, 의존 검사, 빌드로 확인한다

        - 오류가 나지 않아 알아채기 어렵다. 그래픽 카드 자원은 놓아주면서 화면에는 남는다
    - 처리
        - 화면을 받지 않고 메시가 자기 부모에게 빼 달라고 하는 방식으로 만들었다
        - 덱 편성 쪽 29개도 같은 문제일 수 있다. 그쪽 메시가 묶음 안에 있다면 화면에서 안 빠진다. 확인만 해두고 넘긴다
        - **화면에서 뺄 때는 실제 부모에게 빼 달라고 한다.** 화면은 직계 자식만 뺀다
