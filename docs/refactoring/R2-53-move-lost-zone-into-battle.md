# [ETWGL-R2-53] 로스트 존을 전투 상태 안으로 옮긴다

선행: R2-52 │ 후행: R2-54 │ 산출물: Battle 이 내 로스트 존과 상대 로스트 존을 들고 있다 │ Type: Rule │ Domain: Battle LostZone

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 내 로스트 존과 상대 로스트 존이 전투 밖의 저장소에 따로 있다
        - 재접속하면 무엇이 어떤 차례로 쌓였는지를 따로 되돌려야 한다
    - 목적
        - 로스트 존을 전투 한 판 안으로 옮긴다
    - 기대 결과
        - 전투를 통째로 적으면 로스트 존에 쌓인 것도 함께 적힌다
        - 값을 담는 일곱 중 가벼운 넷이 끝난다
    - 건드리지 않는 것
        - 로스트 존을 그리는 것과 눌렀을 때 열리는 것 - 화면이다
        - 되찾는 길 - 그런 카드가 아직 없다. 나오면 그때 낸다

2. 무덤과 따로 만든다
    - 코드가 글자까지 같지만 다른 것이다
    - 무덤 것은 부활할 수 있고 로스트 존 것은 못 한다
    - 왜 나눠 뒀는지를 각자의 파일 맨 위에 적는다. 나중에 합치려는 사람이 이유를 먼저 보게 한다

3. 앞서 정한 모양을 그대로 따른다
    - 값의 타입은 도메인 안에 둔다
    - 그릇은 양쪽이 함께 쓰고, 밖으로 내는 길은 따로 낸다
    - 적어 두기와 되돌리기에 붙인다
    - 옛 저장소는 지운다

4. 쓰던 곳을 바꾸고 옛것을 지운다
    - 로스트 존을 쓰는 곳은 확인용 화면 하나다. 쌓는 곳 셋, 보는 곳 넷
    - 화면에 그리는 쪽은 건드리지 않는다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 내 로스트 존 열기, 상대 로스트 존 열기, 무덤

# Issue

1. 같은 코드를 두 번 쓰는 것이 맞는지 매번 다시 묻게 된다
    - 증상
        - 무덤을 만든 직후라 같은 것을 또 만들었다. 손이 합치자고 한다
    - 원인
        - 판단 근거가 코드 밖에 있다. 카드 설명을 봐야 알 수 있는데 코드에는 안 적혀 있었다
    - 처리
        - 왜 나눴는지를 두 파일 맨 위에 적었다. 다음에 여는 사람이 코드보다 먼저 그 줄을 본다
        - **나눠 둔 이유는 나눠 둔 자리에 적는다.** 문서에만 있으면 코드를 보는 사람에게 안 닿는다

2. 쌓는 곳을 부르는 방식이 곳마다 달랐다
    - 증상
        - 어떤 곳은 미리 받아 둔 것을 쓰고, 어떤 곳은 그 자리에서 저장소를 불렀다
    - 원인
        - 혼자 있는 것이라 어디서든 바로 부를 수 있었다
    - 처리
        - 전투를 통해 부르게 하면서 한 가지로 맞춰졌다
        - **아무 데서나 부를 수 있으면 부르는 방식이 여러 가지가 된다**
