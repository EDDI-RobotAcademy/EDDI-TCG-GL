선행: R2-7 │ 후행: R2-10 │ 산출물: src/battle/card_grid_popup/ │ Type: Structure │ Domain: Battle

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 카드를 격자로 늘어놓고 페이지를 넘기는 팝업을 그리는 파일이 하나 있는데, 이름이 YourLostZonePopupRendererV2 이고 자리가 your_lost_zone 폴더 아래다
        - 그런데 다섯 곳이 쓴다. 내 로스트존, 상대 로스트존, 내 무덤, 상대 무덤, 그리고 레오닉의 부름이 내 덱에서 카드를 고르는 화면
        - 다섯 중 넷이 내 로스트존이 아니다
        - 해골 군주 레오닉(#17)을 구현하면 상대 핸드를 보여주는 화면이 하나 더 늘어 여섯 곳이 된다
        - 그 사람은 상대 핸드 팝업을 찾으려고 내 로스트존 폴더를 뒤질 이유가 없다. 같은 것을 또 만들게 된다
        - 로스트존 작업을 하다 이 파일을 로스트존 전용으로 알고 고치면 나머지 네 곳이 함께 바뀐다
    - 목적
        - 이 파일이 특정 기능이 아니라 여러 화면이 쓰는 부품임을 이름과 자리에 드러낸다
    - 기대 결과
        - 카드 격자 팝업이 필요한 사람이 이름으로 찾는다
        - 로스트존을 고치는 사람이 이 파일을 로스트존 것으로 오해하지 않는다
    - 부품이라고 판단한 근거
        - build 가 배치 값과 카드 목록만 받는다. 무덤, 로스트존, 덱, 레오닉 어느 것도 모른다
        - 파일 안에 도메인 단어가 나오는 여섯 곳은 전부 자기 이름 YourLostZone 뿐이다
        - 카드를 고르는 동작은 렌더러 밖에 있다. 시나리오에 24곳
    - 건드리는 것
        - 팝업 렌더러와 그 배치 값 파일의 이름과 자리
        - 이 둘을 참조하는 곳. 얇은 파일 세 개와 시나리오
    - 건드리지 않는 것
        - 파일 안의 코드 - 자리와 이름만 바꾼다. 하는 일은 그대로다
        - 목적별로 나누는 일 - 지금 나누면 빈 껍데기 다섯 개가 생긴다. 실제로 갈라질 때 나눈다
        - 무덤과 로스트존 패널 렌더러 - 부활 덱이 들어오면 갈라진다 (R2-8 폐기 사유)
        - 카드를 고르는 동작 - 시나리오에 있다. 그대로 둔다

2. 부품인지 다시 확인한다
    - 옮기기 전에 이 파일이 정말 도메인을 모르는지 본다
    - 도메인을 알고 있으면 부품이 아니다. 그때는 옮기지 않고 판단부터 다시 한다

3. 자리와 이름을 옮긴다
    - 여러 화면이 쓰는 부품이므로 특정 화면 폴더 밖으로 꺼낸다
    - 이름에서 특정 화면을 뺀다. 하는 일로 이름을 짓는다
    - 배치 값 파일도 함께 옮긴다. 부품의 설정이므로 부품과 같은 자리에 둔다

4. 참조를 잇고 얇은 파일을 정리한다
    - 얇은 파일 세 개가 새 자리를 가리키게 한다
    - 내 로스트존도 얇은 파일을 갖게 한다. 넷이 대등해야 한다
    - 시나리오의 참조를 고친다

5. 하는 일이 이전과 같은지 확인하고 게임 동작은 달라지지 않는다
    - 다섯 곳의 팝업이 이전과 같이 뜨는지 본다
    - 자리와 이름만 바꾸므로 화면은 이전과 같다

# Issue

1. 파일을 옮긴 뒤 없던 문제가 있는 것처럼 보였다
    - 증상
        - 옮기고 나서 손패 카드를 배틀 필드로 내보내는 동작이 되지 않았다
        - 팝업과 무관한 기능이라 원인을 찾기 어려웠다
    - 원인
        - 개발 서버가 세 개 떠 있었고, 파일을 옮기고 새 폴더를 만들면서 파일 감시가 옛 경로를 붙들고 있었다
        - 브라우저가 옛 번들을 보고 있었다
        - 코드에는 문제가 없었다. 타입 검사, 의존 검사, webpack 빌드가 전부 통과했고 옮긴 파일은 이름 말고 한 글자도 다르지 않았다
    - 처리
        - 개발 서버를 전부 끄고 하나만 다시 켠 뒤 정상 동작을 확인했다
        - 동작 확인 목록에 [파일을 옮긴 뒤에는 개발 서버를 다시 켠다] 를 넣었다

2. 원인을 코드에서만 찾았다
    - 증상
        - 드래그가 안 된다는 말을 듣고 코드 경로부터 뒤졌다. 클릭 처리 순서, 팝업 가드, 순환 참조를 차례로 봤다
    - 원인
        - 옮긴 파일이 이름 말고 같은지를 먼저 확인했어야 했다. 같다면 코드가 원인일 수 없다
        - 확인 순서가 없었다. 값싼 확인부터 하지 않고 비싼 추측부터 했다
    - 처리
        - 확인 순서를 세웠다. 옮긴 파일이 내용상 같은가 → 빌드가 되는가 → 서버가 새 번들을 주는가 → 그다음에 코드
        - 동작 확인 목록에 적었다
