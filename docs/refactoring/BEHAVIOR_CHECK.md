# 동작 확인 목록

> 언제 여는가: 작업을 끝내기 직전. 바꾼 뒤에도 이전과 같이 도는지 확인할 때.
> 되돌려야 할 때는 이 문서 맨 아래 [되돌리기] 를 본다.

R2 리팩토링의 **모든** 티켓이 완료 전에 통과해야 하는 목록이다.
각 백로그는 이 문서를 **링크만** 하고 항목을 복사하지 않는다 (규칙 4).

현재 이 저장소에는 단위 테스트 러너가 없다 (`npm test`는 exit 1 스텁).
따라서 아래는 **수동 실행 절차**이며, 동작이 달라지는 것을 잡아낼 유일한 수단이다.

```
# 파일을 옮기거나 이름을 바꿨다면 먼저 개발 서버를 끈다
#   서버가 옛 경로를 붙들고 있어 브라우저가 옛 번들을 본다.
#   코드는 멀쩡한데 동작이 안 되는 것처럼 보인다 (R2-9 에서 실제로 겪었다)
pkill -f "webpack serve"

npm run draw-field-energy-full-efr
```

브라우저는 강력 새로고침한다.

## 동작이 안 될 때 확인 순서

값싼 것부터 본다. 코드부터 뒤지지 않는다.

```
1. 개발 서버가 하나만 떠 있는가        ps aux | grep "webpack serve"
2. 옮긴 파일이 이름 말고 같은가         같으면 코드가 원인일 수 없다
3. 빌드가 되는가                      npx webpack --config <시나리오>/config/webpack.dev.js
4. 브라우저 콘솔에 오류가 있는가
5. 그다음에 코드를 본다
```

## 되돌리기

동작 확인에서 문제가 나왔는데 바로 고칠 수 없으면 되돌린다.
**고치려고 붙들고 있는 것보다 되돌리는 편이 낫다.** 원인을 모른 채 덧대면
다음 작업까지 오염된다.

### 절차

```
1. 어느 작업의 커밋인지 확인한다      git log --oneline | grep ETWGL-R2-
2. 그 작업의 커밋을 전부 되돌린다     git revert <커밋> ...
3. 이 문서의 확인 항목을 다시 돈다    되돌린 것도 확인해야 한다
4. 무엇이 왜 실패했는지 적는다        그 작업 문서의 Issue
```

### 되돌릴 수 있으려면

- 한 작업의 커밋들이 **한 번에 되돌려지는 단위**여야 한다 (규칙 8)
- 작업 하나에 서로 다른 성격의 변경을 섞지 않는다.
  폴더 이동과 코드 수정을 같이 하면 되돌릴 때 둘 다 사라진다
- 커밋 전에는 되돌릴 수단이 없다. **작업을 끝내면 먼저 커밋하고 확인한다**

### 되돌린 뒤

- 그 작업은 [실패] 로 두고 다시 시작한다. 부분만 살리려 하지 않는다
- 무엇이 실패했는지 Issue 에 남긴다. 같은 방식으로 다시 하면 같은 결과가 나온다
- 실패 원인이 확인 항목에 없었다면 이 문서에 항목을 추가한다
