# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 손패 저장소 셋이 deprecated 라는 이름을 달고 있는데 본편과 확인용 화면이 쓰고 있다
        - 이름이 죽었다고 되어 있어 [안 쓰이는데 왜 남아 있지] 로 읽힌다. 실제로는 방식이 낡았다는 표시다
        - 그래서 셋을 지울지 이름을 뗄지 매번 다시 판단하게 된다
    - 목적
        - 이 표시가 무엇을 뜻하는지, 언제 뗄 수 있는지 정한다
    - 기대 결과
        - 다음에 이 폴더를 열었을 때 무엇을 해야 하는지 문서가 답한다
    - 이번에 하는 것
        - 뜻과 조건과 순서를 정한다. 코드는 바꾸지 않는다
    - 건드리지 않는 것
        - 실제로 옮기거나 지우는 일 - 매달린 것이 많아 여러 작업으로 나뉜다
        - 다른 폴더의 deprecated 표시 - 손패만 본다

2. 이 표시가 무엇을 뜻하는지 정한다
    - 안 쓰인다는 뜻이 아니다. **이 방식으로 더 만들지 마라** 는 뜻이다
    - 실제로 붙은 자리를 보면 안다. 저장소가 화면 덩어리를 직접 들고, 부를 함수를 들고, 크기 조절까지 한다

```
낡은 방식    private currentFieldHandSceneList: THREE.Group[]
             private handAddedCallback
             public resizeHandSceneList(scaleX, scaleY)

새 방식      저장소는 번호만 담는다. 그리는 것은 렌더러, 크기 조절도 렌더러
```

3. 셋이 각각 무엇에 매달려 있는지 센다

| 저장소 | 담는 것 | 새 방식의 대체물 | 본편 | 확인용 화면 |
| --- | --- | --- | --- | --- |
| 손패 카드 번호 목록 | 번호 배열 | 있다 | 없음 | 5개 |
| 손패 카드 자리 목록 | 자리 배열 | 있다 | 없음 | 7개 |
| 손패 화면 덩어리 목록 | THREE.Group 배열, 부를 함수 | **없다** | 2곳 | 12개 |

4. 언제 뗄 수 있는지 조건을 정한다
    - 매달린 것이 하나도 없을 때 뗀다. 그때는 떼는 것이 아니라 지우는 것이다
    - 대체물이 없는 것은 먼저 새 자리를 만들어야 한다. 화면 덩어리를 담는 자리가 새 방식에 아직 없다
    - **매달린 것이 남아 있는데 표시를 떼면 안 된다.** 떼는 순간 새 코드가 이 방식으로 붙는다

5. 어떤 순서로 없애는지 정한다
    - 대체물이 있는 둘부터 한다. 확인용 화면을 새것으로 옮기면 지울 수 있다
    - 화면 덩어리는 새 자리를 만드는 것이 먼저다. 본편 두 곳이 쓰고 있어 동작이 달라질 수 있다

```
1  손패 카드 번호 목록      확인용 화면 5개를 새것으로 옮기고 지운다
2  손패 카드 자리 목록      확인용 화면 7개를 옮기고 지운다
3  화면 덩어리를 담는 새 자리를 만든다
4  본편 두 곳을 새 자리로 옮긴다
5  확인용 화면 12개를 옮기고 지운다
```
