# [ETWGL-R2-64] 사용자가 하는 일과 그 결과로 일어나는 일을 정한다

선행: R2-63 │ 후행: R2-65 │ 산출물: [판정표](R2-64-battle-command-catalog-table.md) │ Type: Strategy │ Domain: Battle

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 전투 상태에 값은 다 모았는데 흐름은 여전히 화면이 조립한다
        - 카드를 한 장 낼 때 화면이 여섯 줄을 순서대로 부른다. 하나만 빠져도 어긋나는데 막을 방법이 없다
        - 애그리게이트를 만든 뜻이 없어졌다
    - 목적
        - 사용자가 하는 일이 무엇이고, 그 결과로 무슨 일이 일어나는지를 정한다
    - 기대 결과
        - 다음 작업부터 [무엇을 옮긴다] 가 아니라 [무엇을 할 수 있게 한다] 로 갈 수 있다
    - 건드리지 않는 것
        - 코드 - 이번에는 판정만 한다
        - 화면을 만지는 일 - 창 크기, 팝업, 쪽 넘기기는 전투와 무관하다

2. 밖에서 오는 것을 사용자가 하는 일 단위로 센다
    - 화면이 부르는 함수 단위가 아니라 사용자가 하는 일 단위로 센다
    - 지금 화면이 그 하나를 몇 줄로 조립하는지 함께 적는다

3. 무엇을 돌려줄지 정한다
    - 지금 상태를 다시 읽게 하면 안 되는 이유를 적는다
    - 화면이 그것으로 무엇을 하는지 함께 적는다

4. 한 번에 안 끝나는 것을 가려낸다
    - 연출 중간에 값이 바뀌는 카드가 있다
    - 그것을 어떻게 다룰지 정한다

5. 게임 동작이 달라지지 않는다
    - 이번에는 판정만 한다. 코드를 안 바꾼다

# Issue

1. 값을 다 모으고도 애그리게이트가 아니었다
    - 증상
        - 전투 상태에 값 아홉을 모았는데, 카드를 한 장 낼 때 화면이 여섯 줄을 순서대로 부른다
    - 원인
        - 티켓을 [무엇을 옮긴다] 로 세웠다. 옮기는 일만 하면 값은 모이고 흐름은 그대로다
    - 처리
        - 규칙 19 로 올렸다. 밖에서 부르는 줄이 한 줄이면 애그리게이트, 여러 줄이면 담아 주는 곳이다
        - **값이 어디 있느냐와 누가 판단하느냐는 다른 문제다**

2. 지금 상태를 다시 읽는 것으로는 안 된다
    - 증상
        - 화면이 전투 상태를 다시 읽어서 그리면 될 것 같았다
    - 원인
        - 상태만 보면 [상대 유닛이 넷이다] 는 알아도 [3번이 베여 쓰러졌다] 는 모른다
        - 무엇이 달라졌는지를 모르면 어떤 연출을 틀지 못 고른다
    - 처리
        - 무슨 일이 있었는지를 일어난 차례대로 돌려주기로 했다
        - **화면은 지금 모습이 아니라 무슨 일이 있었는지를 알아야 그린다**

3. 한 번에 안 끝나는 카드가 있다
    - 증상
        - 시체 폭발은 날아온 것이 하나씩 맞을 때마다 피해가 들어간다
        - 결과를 한 번에 돌려주면 화면이 그 사이를 못 만든다
    - 원인
        - 하나 보내면 하나 돌아온다고만 봤다
    - 처리
        - 돌려주는 것을 목록으로 뒀다. 화면이 그 차례를 연출에 나눠 붙인다
        - **한 번에 끝나는 것만 있다고 여기면 연출이 있는 게임에서 막힌다**
