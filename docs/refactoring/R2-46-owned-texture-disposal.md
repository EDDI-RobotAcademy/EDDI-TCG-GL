# [ETWGL-R2-46] 전투 중 만들어 쓰는 글자 그림의 정리 시점 정의

선행: R2-36 │ 후행: R2-47 │ 산출물: markOwnedTexture, disposeMesh 의 그림 처리 │ Type: Rendering │ Domain: Platform

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 전투 중에 글자를 그려 만드는 그림이 열한 곳에 있는데, 놓아주는 곳이 거의 없다
        - 손패 카드의 에너지 숫자는 값이 바뀔 때마다 새로 만든다. 옛것이 그대로 남는다
        - 연출도 돌 때마다 만든다. 스킬을 쓸 때마다 쌓인다
    - 목적
        - 만든 그림을 언제 놓아줄지 정하고, 놓아주게 한다
    - 기대 결과
        - 숫자가 바뀌어도, 스킬을 여러 번 써도 그림이 쌓이지 않는다
    - 왜 지금 중요해졌나
        - 앞으로 체력, 무기, 에너지, 필드 에너지를 전부 글자로 바꾼다
        - 값마다 그림 파일을 두는 대신 그려서 만든다. 그러면 만들어 쓰는 그림이 훨씬 늘어난다
    - 건드리지 않는 것
        - 덱 편성 화면의 글자 그림 - 같은 규칙이 적용되지만 전투가 아니다. 그쪽도 놓아주지 않고 있다
        - 공유 그림 - 여러 카드가 나눠 쓴다. 한 장이 사라질 때 놓아주면 남은 카드가 깨진다
        - 그림을 글자로 바꾸는 일 - 화면이 달라진다. 별도 작업
        - 덱 편성 화면의 글자 - 전투가 아니다

2. 공유하는 그림과 만들어 쓰는 그림을 가른다
    - 공유 그림은 한 번 읽고 여러 카드가 나눠 쓴다. 개수가 정해져 있어 늘지 않는다
    - 만들어 쓰는 그림은 그 메시 하나만 쓴다. 값이 바뀔 때마다, 연출이 돌 때마다 새로 만든다
    - 재질을 놓아주는 것으로는 그림이 안 놓아진다. 따로 말해야 놓아준다

3. 만든 쪽이 표시하고, 놓아주는 쪽이 표시를 본다
    - 만드는 곳에서 [이 그림은 이 메시만 쓴다] 고 표시한다
    - 놓아주는 곳은 표시가 있는 것만 함께 놓아준다
    - 표시가 없으면 공유 그림이므로 건드리지 않는다

4. 표시할 곳과 놓아줄 곳을 모두 찾는다
    - 만드는 곳을 세고, 그것을 놓아주는 곳이 어디인지 짝을 짓는다
    - 이미 제대로 놓아주는 곳은 건드리지 않는다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 놓아주기 시작했으므로 아직 쓰는 것을 버리지 않는지가 핵심이다
    - 손패 에너지를 여러 번 붙였다 뗐다 해도 숫자가 보이는지
    - 죽음의 낫, 파멸의 계약, 네더 블레이드 등장과 패시브

# Issue

1. 재질을 놓아줘도 그림은 안 놓아진다
    - 증상
        - 손패 에너지 숫자를 갈아 끼울 때 재질을 놓아주고 있었는데도 그림이 쌓였다
    - 원인
        - 재질을 놓아주는 것과 그 재질이 물고 있는 그림을 놓아주는 것은 별개다
        - 그림은 여러 재질이 나눠 쓸 수 있어서 자동으로 안 놓아진다
    - 처리
        - 만든 쪽이 표시하고 놓아주는 쪽이 그 표시를 보게 했다
        - **놓아주는 것이 무엇까지 놓아주는지 확인한다.** 한 겹 안쪽은 안 따라간다

2. 놓아주는 방식이 곳마다 달랐다
    - 증상
        - 연출마다 자기 놓아주기 함수를 갖고 있었다. 어떤 것은 그림까지 놓아주고 어떤 것은 아니었다
    - 원인
        - 공통 함수가 있는데 연출들이 각자 만들어 썼다
    - 처리
        - 이번에는 각자의 함수에 같은 처리를 넣었다. 공통 함수로 모으는 것은 연출 코드를 손대는 일이라 따로 본다
        - **같은 일을 하는 함수가 곳마다 있으면 고칠 때 다 찾아야 한다**
