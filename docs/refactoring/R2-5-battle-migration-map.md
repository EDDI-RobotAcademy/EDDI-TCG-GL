# [ETWGL-R2-5] battle 폴더와 하위 구획을 만들어 리팩토링 시 이동할 장소 결정 전략 수립

선행: R2-3 │ 후행: R2-6 │ 산출물: docs/battle_migration_map.md │ Type: Strategy │ Domain: Battle

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - src 아래 폴더가 240개인데 그중 무엇이 전투에 속하는지 정리된 적이 없다
        - 옮기기 시작하면 폴더마다 그때그때 갈 곳을 정하게 되고, 판단이 사람과 시점에 따라 달라진다
        - 한 폴더가 두 구획에 걸치는 경우가 있다. 속성 마크는 유닛인지 손패인지 옮길 때마다 다시 고민하게 된다
        - 어떤 순서로 얼마씩 옮겨야 되돌릴 수 있는 크기인지 정해진 것이 없다
        - 계획 없이 옮기면 중간에 멈췄을 때 어디까지 했는지 알 수 없다
    - 목적
        - 전투에 속하는 폴더를 빠짐없이 가려내고 각각이 갈 자리를 미리 정한다
        - 어떤 순서로 얼마씩 옮길지 정해서 실행 작업으로 넘긴다
    - 기대 결과
        - 옮기는 사람이 폴더마다 판단하지 않고 표를 보고 그대로 옮긴다
        - 중간에 멈춰도 어디까지 했고 무엇이 남았는지 표에서 확인한다
        - 옮기는 도중에 자리가 바뀌지 않으므로 같은 폴더를 두 번 옮기지 않는다
    - 건드리는 것
        - docs/battle_migration_map.md 신설
    - 건드리지 않는 것
        - 소스 코드 - 이 작업은 계획만 세운다. 실제 이동은 R2-6 이후다
        - 폴더 내용 - 어디로 갈지만 정하고 파일 안은 열지 않는다
        - 덱, 컬렉션, 상점, 로비 폴더 - 전투가 아니다. 해당 화면을 손볼 때 같은 방식으로 한다
        - 흡수 대상의 실제 흡수 - *_position 과 *_detect 가 어디로 흡수되는지 적기만 하고 실행하지 않는다

2. 옮길 대상을 빠짐없이 목록으로 만든다
    - src 240개 중 전투에 속하는 것을 가려낸다
    - 전투인지 아닌지 애매한 폴더는 판단 근거와 함께 남긴다
    - 옮기지 않기로 한 것도 사유와 함께 적는다. 나중에 빠뜨린 것인지 뺀 것인지 구분되어야 한다

3. 각 폴더가 갈 자리를 정한다
    - battle 아래 구획을 정하고 폴더마다 목적지를 배정한다
    - 한 폴더가 두 구획에 걸치면 어느 쪽인지와 그 근거를 남긴다
    - *_position 과 *_detect 처럼 다른 폴더에 흡수될 것은 흡수될 대상을 적는다
    - 오타가 있는 폴더 이름은 옮기면서 고칠 것을 표시한다

4. 어떤 순서로 얼마씩 옮길지 정한다
    - 폴더별로 외부에서 참조되는 횟수를 재서 적은 것부터 배열한다
    - 한 번에 옮길 묶음의 크기를 정한다. 되돌릴 수 있고 동작이 달라지지 않았는지 확인할 수 있는 크기여야 한다
    - 묶음마다 실행 작업 번호를 미리 배정한다
    - 첫 묶음은 방식을 확인하는 용도로 가장 안전한 것을 고른다

5. 문서만 만들고 게임 동작은 건드리지 않는다
    - 계획 문서만 추가하고 소스 코드는 옮기지 않는다
    - 표에 적힌 목적지가 R2-3 의 의존 규칙과 어긋나지 않는지 확인한다

2. 전투인지 아닌지 헷갈리는 폴더가 하나 있었다
