# [ETWGL-R2-3] 폴더 구조를 바꿔도 잘못된 의존이 자동으로 발견되도록 의존성 검사 도입

선행: R2-2 │ 후행: R2-5 │ 산출물: .dependency-cruiser.js, scripts/check-domain-purity.js

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 이 저장소에는 의존 방향을 검사할 수단이 없다
        - 타입 검사는 전투 규칙 코드가 화면 라이브러리를 가져다 써도 통과시킨다
        - 지금까지 화면 배치 파일 31개가 화면 라이브러리를 한 번도 쓰지 않은 것은 순전히 사람의 규율 덕분이다
        - 앞으로 폴더 31개를 옮기는 동안에는 규율만으로 지킬 수 없다
    - 목적
        - 코드가 지켜야 할 구조 규칙을 문서가 아니라 자동 검사로 바꾼다
    - 기대 결과
        - 개발자가 폴더를 옮기거나 새 코드를 넣을 때, 모든 참조를 사람이 직접 훑어보지 않아도 잘못된 방향이 즉시 발견된다
        - 이후 여덟 건의 작업이 자동 검증 위에서 진행된다
    - 건드리는 것
        - 검사 도구 설치, 규칙 파일, 검사 스크립트, 실행 명령
    - 건드리지 않는 것
        - 소스 코드 - 이 작업은 검사 도구만 넣는다. 기존 위반이 나와도 여기서 고치지 않는다
        - 도구 도입과 위반 수정을 한 커밋에 섞으면 되돌릴 수 없다
        - 코드 스타일 검사 - 스타일은 지금 문제가 아니다. 의존 방향만 본다
        - 자동 빌드 연동 - 팀 합의가 필요하다. 로컬 명령으로 충분하다
        - 기존 폴더 전수 조사 - 규칙은 새로 만들 경로에만 건다

2. 명령 하나로 잘못된 의존을 찾는다
    - 검사 도구를 붙이고 명령 한 줄로 전체를 훑는다
    - 위반이 있으면 실패로 끝나 그냥 지나칠 수 없게 한다
    - 어느 파일이 어느 규칙을 어겼는지 함께 알려준다

3. 지켜야 할 구조 규칙을 코드로 옮긴다
    - 전투 규칙 코드가 화면 라이브러리를 쓰지 못하게 막는다 - 저장과 복원의 전제
    - 공용 기반 코드가 게임 내용을 알지 못하게 막는다 - 다른 화면에서 재사용하려면
    - 서로 다른 화면의 코드가 직접 얽히지 못하게 막는다
    - 전투 계산이 매번 같은 결과를 내도록 무작위와 현재 시각 사용을 막는다
    - 각 규칙 옆에 왜 막는지 이유를 적는다

4. 규칙이 실제로 걸리는지 확인한다
    - 일부러 규칙을 어긴 파일을 만들어 전부 걸리는지 보고 지운다
    - 검사할 폴더가 아직 없는 상태에서도 오류 없이 통과하게 한다
    - 아직 없어서 통과한 것과 규칙이 동작해서 통과한 것을 구분한다

5. 이미 있던 위반은 남기고 게임 동작은 건드리지 않는다
    - 기존 위반은 실패가 아니라 경고로 남겨 검사가 첫날부터 무력해지지 않게 한다
    - 각 위반을 어느 작업이 맡을지 적어둔다
    - 검사 도구만 추가하고 소스 코드는 한 줄도 고치지 않는다
    - 자동으로 잡을 수 없는 것이 무엇인지 적어둔다 - 도구를 넣고 안심하지 않도록

# Issue

1. 가장 중요한 규칙이 조용히 통과하고 있었다
    - 증상
        - 전투 규칙 코드가 화면 라이브러리를 쓰지 못하게 하는 규칙이, 일부러 위반을 만들어도 걸리지 않았다
        - 다른 두 규칙은 정상 발화했다
    - 원인
        - 설정에서 외부 라이브러리 폴더를 검사 대상에서 제외해 두었다
        - 제외하면 그 참조가 그래프에서 통째로 사라져 규칙이 볼 대상이 없어진다
        - 들어가지 않게만 하고 참조는 남기는 설정을 써야 했다
    - 처리
        - 설정을 고쳤다
        - 위반 프로브를 돌리지 않았다면 폴더를 실제로 만드는 시점까지 몰랐을 문제다
        - 이 경험을 근거로 [규칙을 추가할 때는 위반 프로브로 발화를 확인한다] 를 계획서에 항목으로 넣었다

2. 계획했던 규칙 하나를 이 도구로 만들 수 없었다
    - 증상
        - 계획서에 [전투 계산에서 무작위 사용 금지] 를 검사 규칙으로 적었는데 구현할 수 없었다
    - 원인
        - 이 도구는 파일 사이의 참조만 검사한다
        - 무작위 호출은 참조가 아니라 전역 함수 호출이라 검사 대상이 아니다
    - 처리
        - 별도 스크립트로 분리했다
        - 분리한 김에 현재 시각 조회도 함께 막았다. 시각도 매번 값이 달라지므로 같은 문제다

3. 첫 실행부터 실패해 게이트로 쓸 수 없었다
    - 증상
        - 기존 코드에 순환 참조가 여섯 건 있어 검사가 처음부터 실패로 끝났다
        - 이러면 이후 작업에서 아무도 결과를 보지 않게 된다
    - 원인
        - 순환 참조 규칙을 전체 코드에 실패 등급으로 걸었다
    - 처리
        - 두 단으로 나눴다
        - 새로 만들 전투 폴더는 실패, 기존 코드는 경고로 둔다
        - 여섯 건은 담당 작업을 배분해 기록만 남겼다
