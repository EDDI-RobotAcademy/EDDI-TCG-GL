# Issue

1. 적어 둔 것으로 판을 되돌리는 문이 쓸 수 없는 상태였다
    - 증상
        - 되돌린 뒤 카드를 뽑으면 번호 0 을 주고, 손패에 이미 있는 0 번과 겹친다
    - 원인
        - 번호를 하나 줄 때마다 다음 번호를 뒤로 미뤄 두는데, 그 미루는 일이 [손패에 넣는다] [필드에 놓는다] 안에 있다
        - 되돌릴 때는 손패와 필드를 적어 둔 것에서 바로 채우므로 그 자리를 안 지난다
        - 번호가 겹치면 화면이 그 번호로 가리키던 것과 전투가 그 번호로 찾는 것이 달라진다
    - 처리
        - 되돌린 뒤 적어 둔 것에 있는 가장 큰 번호보다 뒤로 밀어 둔다
        - **부르는 곳이 0 인 것은 도는지 확인된 적이 없다.** 이 문은 재접속용으로 만들어 두고 아무도 안 불렀다. 그것을 유일한 길로 쓰기로 했으니 먼저 도는지 봐야 했다
        - 부르는 곳이 0 이던 이유가 이것이었을 수 있다

2. 읽기 창구를 판보다 먼저 받고 있었다
    - 증상
        - 판을 차리는 자리를 뒤로 옮기니 읽기 창구가 빈 판을 가리켰다
    - 원인
        - 읽기 창구는 받을 때의 판을 붙들고 있다. 전에는 빈 판을 먼저 만들고 그 판을 제자리에서 고쳤으므로 순서가 문제가 안 됐다
        - 지금은 차리는 순간에 판이 새로 생긴다
    - 처리
        - 읽기 창구를 받는 자리를 판을 차린 뒤로 옮겼다. 구역 넷이 그 창구를 바로 쓰므로 그보다도 앞이다
        - **차린 다음에 읽는다.** 진짜 대전도 같은 순서다 — 상태가 도착하고 나서 읽는다

| | 길 1 — 차리는 동안만 빌려준다 | 길 2 — 값으로 적는다 |

길 1 은 문을 닫은 것이 아니라 문 이름만 바꾼 것이다. 화면에서도 `세션.빌려줘( 판 => 판을 고친다 )`
를 쓸 수 있고, 타입을 추론으로 받으니 검사도 그대로 못 잡는다.

## 들어오는 문이 하나가 됐다

```
확인용 판  →  적어 둔 것(값)  →  세션  →  판을 차린다
서버       →  적어 둔 것(값)  →  세션  →  판을 차린다
```

적어 두는 쪽만 바뀌고 문은 같다. 네트워크가 붙을 때 문을 새로 만들지 않는다.

**만들 것이 거의 없었다.** 판 하나를 통째로 적어 두는 것과 그것으로 되돌리는 문은 재접속용으로
이미 있었다. 확인용 판이 만지던 열 개가 그 적어 둔 것의 칸에 하나씩 대응했다.

| 만지던 것 | 적는 칸 |
| --- | --- |
| 에너지를 세팅한다 | 양쪽 필드 에너지 |
| 덱을 깐다 | 양쪽 덱 (순서까지) |
| 무덤에 보낸다 × 열둘 | 양쪽 무덤 (쌓인 차례까지) |
| 로스트 존에 보낸다 × 열둘 | 양쪽 로스트 존 |
| 손패에 넣는다 × 열둘 | 손패 |
| 상대 필드에 놓는다 × 일곱 | 상대 필드 (체력, 붙은 에너지, 종족별로) |

| 구분 | 내용 |
| --- | --- |
| **잘 맞은 것** | 새로 만든 것이 거의 없다. 재접속용으로 있던 것이 그대로 맞았다. |
| **잘 맞은 것** | 검사를 붙이는 대신 닿는 길을 없앴다. 검사는 어긴 뒤에 알려 주고, 길이 없으면 어길 수가 없다. |
| **잘 맞은 것** | 확인용 판도 전투 상태를 안 만지게 됐다. 목표는 화면까지였는데 한 겹 더 갔다. |
| **미흡한 것** | 부르는 곳이 0 인 문을 유일한 길로 쓰기로 하면서, 그 문이 도는지 먼저 안 봤다. 번호 겹침을 뒤늦게 찾았다. |
