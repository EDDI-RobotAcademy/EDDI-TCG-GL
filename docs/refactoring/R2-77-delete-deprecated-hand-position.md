# [ETWGL-R2-77] 낡은 손패 자리 계산을 없애고 본편과 같은 자리에 서게 한다

선행: R2-76 │ 후행: R2-78 │ 산출물: deprecated_repository 셋 중 둘이 없어졌다 │ Type: Structure │ Domain: Battle Hand

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 손패가 서는 자리를 재는 곳이 둘이다. 본편이 쓰는 것과 낡은 방식 표시가 붙은 것
        - 둘의 기준 숫자가 다르다. 확인용 화면 넷이 옛것을 써서 손패가 다른 자리에 선다
    - 목적
        - 낡은 것을 없애고 그 넷이 본편과 같은 자리에 서게 한다
    - 기대 결과
        - 손패가 서는 자리를 재는 곳이 하나가 된다
    - 건드리지 않는 것
        - 화면 덩어리를 담는 것 - 본편도 쓴다. R2-78 부터

2. 두 계산이 얼마나 다른지 잰다
    - 눈으로 보지 말고 값을 넣어 센다
    - 1920×1080 에서 오른쪽으로 88, 아래로 86 이다. 눈에 띈다

3. 어느 쪽이 맞는지 정한다
    - 본편이 쓰는 것이 맞다. 확인용 화면 중 가장 최신인 것도 그것을 쓴다
    - 옛것을 쓰는 넷의 모습이 달라진다. 그것이 맞는 자리다

4. 가져오기만 하는 줄도 걷어낸다
    - 부르지 않고 가져오기만 하는 화면이 셋 더 있다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 손패 자리, 드래그
    - 집는 자리와 놓는 자리가 어긋나지 않는지

# Issue

1. 지우면 보이는 모습이 달라지는 경우였다
    - 증상
        - 지금까지 낡은 것을 지울 때는 안 쓰는 것이라 모습이 안 바뀌었다
        - 이번에는 쓰는 곳이 있고, 두 계산의 값이 달랐다
    - 원인
        - 언제 어느 쪽이 바뀌었는지 기록이 없다. 본편만 새것으로 옮기고 옛 화면은 두었다
    - 처리
        - 어느 쪽이 맞는지 물어 정하고 옮겼다
        - **낡은 것을 지울 때 쓰는 곳이 있으면 값이 같은지 먼저 잰다.** 다르면 어느 쪽이 맞는지 정해야 한다

2. 얼마나 다른지 눈으로 안 보고 값으로 셌다
    - 증상
        - 기준 숫자가 다른 것은 코드로 보이는데, 화면에서 얼마나 옮겨지는지는 안 보인다
    - 원인
        - 계산이 화면 크기와 섞여 있다. 가로와 세로가 다른 비율로 들어간다
    - 처리
        - 1920×1080 을 넣어 자리 넷과 세로를 대 봤다
        - **비율로 된 자리는 실제 크기를 넣어 봐야 얼마나 다른지 안다**

3. R2-30 기준이 이 경우를 안 다룬다
    - 증상
        - [본편이 안 쓰고, 새 코드가 있고, 매달린 화면이 적으면 지운다] 로는 지우는 쪽인데, 지우면 모습이 달라진다
    - 원인
        - 그 기준은 안 쓰는 코드를 지울 때를 보고 만들었다
    - 처리
        - 이번 판단을 규칙에 붙일지는 다음에 본다. 같은 경우가 또 나오면 붙인다
        - **기준을 만들 때 본 경우 밖의 것이 나오면 기준을 늘리기 전에 한 번 더 나오는지 본다**
