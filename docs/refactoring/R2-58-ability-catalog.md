# [ETWGL-R2-58] 카드를 추가할 때 코드 수정 없이 데이터로 정의할 수 있도록 능력 정의 구조 도입

선행: R2-57 │ 후행: R2-59 │ 산출물: [카드 능력 판정표](R2-58-ability-catalog-table.md) │ Type: Strategy │ Domain: Battle Ability

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 카드 열두 장의 규칙이 확인용 화면 파일 하나 안에 들어 있다. 3,827 줄이다
        - 본편에는 규칙이 한 줄도 없다. 공격해도 체력이 안 줄고 무덤에 안 간다
        - 카드가 백 장인데 열두 장만 만들어져 있다. 남은 여든여덟 장을 같은 방식으로 넣으면 그 파일이 계속 커진다
    - 목적
        - 카드마다 다른 것과 카드마다 같은 것을 가른다. 같은 것은 뼈대로, 다른 것은 값으로 적는다
    - 기대 결과
        - 카드를 더할 때 값을 적는 것으로 끝나는 범위가 정해진다
        - 값으로 안 되는 것이 무엇인지도 함께 드러난다
    - 왜 순서를 바꿨나
        - 원래 이 일이 [연출 도중 종료되어도 상태가 일관되게] 뒤였다
        - 그런데 본편에 갈라낼 상태 변화가 없다. 규칙을 꺼내는 일이 먼저다
    - 건드리지 않는 것
        - 확인용 화면의 동작 - 이번에는 판정만 한다. 옮기는 것은 다음이다
        - 연출 - 규칙과 연출을 가르는 것은 R2-59 다

2. 카드 열두 장이 실제로 무엇을 하는지 적는다
    - 코드가 아니라 카드 설명으로 적는다
    - 무엇을 고르는가, 무엇이 일어나는가, 얼마인가를 나눠 적는다

3. 카드마다 같은 것을 찾는다
    - 고르는 방식이 몇 가지인지 센다
    - 일어나는 일이 몇 가지인지 센다
    - 같은 것이 반복되면 그것이 뼈대가 된다

4. 값으로 안 되는 것을 가려낸다
    - 값 하나로 적을 수 있는 것과, 카드마다 다른 판단이 필요한 것을 나눈다
    - 값으로 안 되는 것은 왜 안 되는지 적는다

5. 게임 동작이 달라지지 않는다
    - 이번에는 판정만 한다. 코드를 안 바꾼다

# Issue

1. 규칙이 확인용 화면 안에 있었다
    - 증상
        - 본편에서 공격하면 연출만 돈다. 상대 체력이 안 줄고 쓰러진 유닛이 무덤에 안 간다
        - 그 규칙이 전부 확인용 화면 파일 하나 안에 있다
    - 원인
        - 카드를 하나씩 만들 때마다 그 화면에서 눈으로 보며 붙여 왔다
    - 처리
        - 이번 판정으로 무엇이 뼈대이고 무엇이 값인지 정했다. 옮기는 것은 다음이다
        - **눈으로 보며 만든 것은 보던 자리에 남는다.** 옮길 자리를 먼저 정해 두지 않으면 그렇게 된다

2. 순서가 뒤바뀌어 있었다
    - 증상
        - [연출 도중 종료되어도 상태가 일관되게] 가 먼저였는데, 갈라낼 상태 변화가 본편에 없었다
    - 원인
        - 계획을 세울 때 본편에 규칙이 있다고 여겼다
    - 처리
        - 두 번호를 맞바꿨다. 아직 손대지 않은 번호라 바꿀 수 있었다
        - **앞선 작업을 정할 때는 그 작업이 다룰 것이 실제로 있는지 먼저 센다**
