# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 패널과 버튼 메시를 담는 곳이 [어느 버튼을 골랐는가] 까지 들고 있었다
        - 고른 버튼 값은 화면에 그려지는 것이 아니다. 메시와 함께 있을 이유가 없다
    - 목적
        - 고른 버튼 값의 주인을 따로 둔다
    - 기대 결과
        - 화면을 다시 그리는 일과 고른 것을 취소하는 일이 서로 묶이지 않는다
    - 건드리지 않는 것
        - 패널을 닫는 일곱 곳을 하나로 묶는 일 - 앞뒤에 붙은 네온 테두리 정리가 곳마다 달라 범위를 넘는다. R2-69
        - 화면과 카메라를 들고 있는 것 - R2-55
        - 버튼을 만드는 일 - R2-56

2. 고른 버튼 값이 어디에 속하는지 판정한다
    - THREE 객체가 아니다. 다시 시작하면 처음으로 돌아가도 된다
    - 판정 기준으로 Store 다. Cache 가 아니다

3. 값이 언제부터 언제까지 살아 있어야 하는지 확인한다
    - 버튼을 눌러도 패널은 안 닫힌다. 상대 쪽에 네온 테두리만 켜진다
    - 값은 상대 유닛을 누를 때까지 살아 있어야 한다. 그때 이 값을 보고 무엇을 발동할지 정한다
    - 따라서 [버튼을 골랐다] 와 [패널을 닫는다] 는 애초에 같이 일어나지 않는다

4. 패널을 닫는 곳이 전부 값을 되돌려야 하는지 확인한다
    - 여섯은 고르기를 그만두는 자리다
    - 하나는 발동이 끝난 뒤 정리하는 자리다
    - 일곱 모두 되돌려야 한다. 안 되돌리면 다음에 상대 카드를 눌렀을 때 방금 쓴 것이 또 나간다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 일반 공격, 스킬, 상세 보기, 패널 닫기
    - 발동이 끝난 뒤 상대 유닛을 다시 눌렀을 때 아무 일도 안 일어나야 한다

# Issue

1. 닫는 곳이 일곱인데 하는 일이 같은지 알기 어려웠다
    - 증상
        - 카드를 고르고 우클릭해서 패널을 열고 거기서 고르면 발동하는 흐름이라, 닫는 자리마다 뜻이 달라 보였다
    - 원인
        - 닫는 이유가 곳마다 다르다. 다른 카드를 눌렀다, 우클릭으로 닫았다, 발동이 끝났다
    - 처리
        - 이유는 달라도 고른 버튼 값에 대해서는 일곱이 같은 일을 한다. 전부 처음으로 돌린다
        - **닫는 이유가 다른 것과 닫을 때 하는 일이 다른 것은 별개다**

2. 메시를 치우는 함수가 두 가지 일을 겸하고 있었다
    - 증상
        - 값의 주인을 옮기면 되돌리는 자리가 사라진다
    - 원인
        - 값이 메시 저장소 안에 있어서 치우는 김에 같이 돌려졌다. 일부러 그런 것이 아니라 같이 있어서 그랬다
    - 처리
        - 값은 새 저장소로 옮기고, 치우는 함수는 새 저장소에 되돌리라고 한 줄 부른다
        - **값을 들고 있는 것과 되돌리라고 부르는 것은 다르다.** 주인은 새 저장소다
