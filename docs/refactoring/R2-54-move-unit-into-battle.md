# [ETWGL-R2-54] 필드에 나온 유닛을 전투 상태 안으로 옮긴다

선행: R2-53 │ 후행: R2-55 │ 산출물: Battle 이 필드에 나온 유닛을 들고 있다 │ Type: Rule │ Domain: Battle Unit

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 필드에 나온 유닛이 전투 밖의 저장소에 있다
        - 그 저장소가 세 가지를 함께 들고 있다. 유닛 목록, 유닛 사이 간격, 화면에 알리는 통로
        - 화면에 알리는 통로가 있어서 값을 담는 곳이 화면을 알고 있다
    - 목적
        - 유닛을 전투 한 판 안으로 옮기고, 값이 아닌 둘을 갈라낸다
    - 기대 결과
        - 전투를 통째로 적으면 필드에 나온 유닛도 함께 적힌다
        - 값을 담는 곳이 화면을 모르게 된다
    - 건드리지 않는 것
        - 유닛을 그리는 것 - 화면이다
        - 옛 드래그로 필드에 놓는 길 - 아직 확인용 화면이 쓴다. 전투를 보게만 바꾼다
        - 유닛 번호를 매기는 방식 - 화면을 새로 열면 처음부터 다시 센다. R2-57

2. 저장소가 들고 있던 셋을 가른다
    - 유닛 목록은 값이다. 전투 안으로 간다
    - 유닛 사이 간격은 화면 자리다. 게다가 부르는 곳이 없다. 지운다
    - 화면에 알리는 통로는 없앤다. 유닛을 내보내는 쪽이 전투에 담고 그리라고 시킨다

3. 유닛을 도메인 안으로 옮긴다
    - 유닛과 거기 붙는 셋을 도메인 폴더로 옮긴다
    - 옮기고 나면 THREE 금지, 무작위 금지, 현재 시각 금지가 검사로 걸린다
    - 적어 두는 모양과 되돌리는 길을 붙인다. 되돌릴 때 번호를 그대로 살린다

4. 죽은 코드를 지우고 산 코드는 옮긴다
    - 아무도 만들지 않는 드래그 관리자가 있다. 같은 코드가 두 벌이다. 지운다
    - 받아만 두고 안 쓰는 줄이 확인용 화면 일곱에 있다. 걷어낸다
    - 옛 드래그로 놓는 길과 자리 맞추는 함수는 아직 쓰인다. 전투를 보게 바꾼다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 유닛 그리기 화면 셋
    - 옛 드래그로 필드에 놓기 화면 셋

# Issue

1. 값을 담는 곳이 화면에 알리고 있었다
    - 증상
        - 저장소가 유닛을 받으면 등록해 둔 함수를 불러 화면에 그리게 했다
    - 원인
        - 담는 일과 그리는 일을 잇는 자리가 없어서 담는 쪽에 붙였다
    - 처리
        - 통로를 없애고, 유닛을 내보내는 쪽이 전투에 담고 그리라고 시키게 했다
        - **담는 곳이 화면을 알면 담는 곳을 옮길 때마다 화면이 따라온다**

2. 알림 자리가 하나뿐이라 나중에 등록한 것이 이긴다
    - 증상
        - 알림을 받을 곳을 담아 두는 자리가 하나였다. 화면이 둘이면 뒤엣것만 그려진다
    - 원인
        - 혼자만 있는 저장소에 자리를 하나만 뒀다
    - 처리
        - 통로 자체를 없애면서 사라졌다
        - **하나만 담기는 자리는 둘 이상이 등록할 수 있는지부터 본다**

3. 전투를 거치게 하면 전투가 먼저 있어야 한다
    - 증상
        - 옛 드래그 화면 셋이 전투를 시작하지 않는데 필드에 놓을 때 전투를 찾는다
        - 카드를 필드 안쪽에 정확히 떨어뜨리는 순간에만 드러난다. 밖에 떨어뜨리면 그 줄까지 안 간다
    - 원인
        - 옮기기 전에는 저장소가 혼자 있어서 아무 때나 부를 수 있었다
        - 전투를 거치게 하면서 새 조건이 생겼는데 부르는 쪽이 그 조건을 만족하는지 안 봤다
    - 처리
        - 그 화면 셋이 전투를 시작하게 했다
        - **한 곳에 모으면 순서가 생긴다.** R2-51 에서는 덱을 채우는 순서였고 이번은 화면이 전투를 시작하는 순서다
        - **조건이 생기면 부르는 곳을 전부 세어 조건을 만족하는지 확인한다**

4. 같은 코드가 두 벌 있었고 한 벌은 아무도 안 만들었다
    - 증상
        - 드래그 관리자가 옛것과 새것 두 벌인데 새것을 만드는 곳이 한 군데도 없다
    - 원인
        - 새로 만들면서 옛것을 못 지웠고, 새것으로 갈아타지도 않았다
    - 처리
        - 아무도 안 만드는 쪽을 지웠다. 죽은 코드를 옮기면 새 자리에 죽은 코드가 생긴다
        - **옮기기 전에 그것이 살아 있는지부터 센다**
