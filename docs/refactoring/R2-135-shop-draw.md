# Issue

1. 카드 자료의 열쇠를 카드 번호로 썼다 — 사용자가 찾았다
    - 증상
        - 확인 화면은 뜨는데 [예] 를 누르면 아무 일도 안 났다
    - 원인
        - 카드 자료의 열쇠가 0 부터 세는 차례이고, 카드 번호는 [카드번호] 칸에 따로 있다
        - 열쇠를 번호로 써서 `card/0.png` 같은 없는 그림을 찾았다
        - 그림 한 장을 못 읽으면 결과 화면이 **통째로** 안 떴다. 그래서 [아무 일도 안 난다] 로만 보였다
    - 처리
        - [카드번호] 칸을 쓴다. 그리고 그림 한 장을 못 읽어도 나머지는 보여 주고 무엇을 못 읽었는지 적는다
        - **자료의 열쇠가 그 자료의 번호라고 가정하지 않는다.** 열쇠는 담아 둔 차례일 수 있다
        - **한 조각이 실패하면 전체가 안 보이는 구조는 원인을 숨긴다.** 열 장 중 한 장이 없으면 아홉 장을 보여 주는 편이 낫다

2. 카드 세로 비율을 두 번째로 적었다 — 사용자가 찾았다
    - 증상
        - 카드가 납작하게 나왔다
    - 원인
        - 세로 비율은 **가로 대비** 값인데 창 **높이** 에 곱했다. 1920x1080 에서 373px 여야 할 것이 209px 가 됐다
        - 그리고 그 값(1.618)을 새로 적었다. 전투 손패에 이미 1.615 가 있었다
    - 처리
        - 카드 생김새를 `card/shape` 한 곳에 두고 전투와 상점이 같이 읽는다
        - 세로 값을 굳혀 두지 않고 다시 잴 때마다 카드 폭에서 낸다 — 창 모양이 바뀌면 달라지는 값이라 굳힐 수 없다
        - **R2-133 에서 [두 단위가 섞이면 언젠가 섞인다] 고 적어 놓고 그 다음 티켓에서 그렇게 했다.** 같은 이름의 값이 어느 단위인지 값 자체에 적어 두지 않으면 규칙을 적어도 안 막힌다

3. 카드 크기를 근거 없는 숫자로 적었다 — 사용자가 찾았다
    - 증상
        - `cardWidthRatio: 0.12` 라고 적었다. 왜 0.12 인지 아무 데도 없다
    - 원인
        - 전투에 이미 쓰는 값(0.0649)이 있는데 그것과 상관없는 숫자를 골랐다
    - 처리
        - 상점이 아는 것만 적는다 — [다섯 칸이 창 너비의 66%], [두 줄이 창 높이의 72%]. 카드 폭은 둘 중 작은 쪽에서 나온다
        - 너비만 보면 2560x1080 같은 창에서 두 줄이 화면 높이 103% 를 넘었다
        - **숫자를 적을 때는 무엇에 대한 숫자인지가 그 자리에 있어야 한다** (규칙 11)

```
뽑기 단추 → 확인 화면 → 예 → 카드 열 장 → 아무 곳이나 눌러 닫기
                      → 아니오 → 닫힌다
```

```
뽑기 누름 → [뽑는 창구] → 카드 번호 열 개 → 화면에 그린다
              ↑
            지금은 이 안에서 굴린다. 서버가 붙으면 서버에 묻는다
```

전투에서 [적어 둔 것으로 판을 차린다] 를 한 문으로 만든 것과 같은 모양이다 (규칙 25).
