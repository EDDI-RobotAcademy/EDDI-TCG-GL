선행: R2-136 │ 후행: — │ 산출물: 카드 한 장 크게 보기 겹 │ Type: Rendering │ Domain: Shop

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 뽑은 카드에 무슨 능력이 적혔는지 못 읽는다
        - **열 장을 한 화면에 놓는 한 카드는 화면 폭의 1/5을 못 넘는다.** 1920 화면에서
          258픽셀이고, 카드에 찍힌 설명 글자는 9픽셀이 된다
        - R2-136 에서 판을 10% 키웠지만 그것으로는 안 된다. 판을 키워 될 일이 아니다
    - 목적
        - 카드 한 장만 따로 크게 띄운다
    - 기대 결과
        - 무엇을 뽑았는지 읽고 나간다
    - 건드리지 않는 것
        - 뽑기 판의 크기와 배치 - R2-136 에서 정했다
        - 내 카드 화면의 크게 보기 - 덱이 붙을 때 정리한다 (R2-147)

2. 이미 있는 것을 쓸 수 있는지 먼저 본다
    - 내 카드 화면에 크게 보기가 있다 (`my_card_screen_detail_card`)
    - **쓸 수 있으면 쓰고, 못 쓰면 왜 못 쓰는지를 남긴다**

3. 누름을 가른다
    - 카드 한 장을 누르는 길이 이미 있다 (뒤집기). 크게 보기를 어디에 붙일지 정한다

4. 열 장을 이어서 볼 수 있게 한다
    - 한 장 보고 닫고 다시 누르기를 열 번 하게 두지 않는다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 크게 보기, 좌우 넘기기, 닫기, 창 크기 조절

## 누름을 가른 방식

```
덮여 있는 카드를 누른다  →  뒤집는다
드러난 카드를 누른다     →  크게 본다
```

기다리기 싫은 사람은 눌러서 먼저 뒤집고, 읽고 싶은 사람은 한 번 더 누른다.
**한 장씩 다시 덮는 길은 없앴다** — 그럴 일이 없고, 있으면 [전체 뒤집기] 가 한다.

## 있는 것을 왜 안 썼나

내 카드 화면에 크게 보기가 있다. 보고 나서 안 쓰기로 했고, 이유를 `CardZoomFrame` 머리에
적어 뒀다.

| | |
| --- | --- |
| 층이 다르다 | 그쪽은 THREE 로 그린다. 뽑기 결과는 화면 위에 얹는 겹(DOM)이라, 이미 그림으로 떠 있는 것을 다시 메시로 만들 이유가 없다 |
| 담는 방식이 다르다 | 그쪽은 **내 카드 전부를 미리 만들어 두고 보일지 말지만** 바꾼다. 뽑기는 **방금 뽑은 열 장 중 지금 이것 하나**다 |

생김새가 비슷하다고 합치면 한쪽이 바뀔 때 다른 쪽이 딸려 온다.

## 값을 두 번 적지 않는다

```
createCardZoomFrame(뽑기 판 값)
  ├ cardImage   ← 그대로 물려받는다
  └ gradeLook   ← 그대로 물려받는다
```

카드 그림 경로와 등급 색이 두 곳에 있으면 한쪽만 고쳐진다.
