# [ETWGL-R2-65] 손패에서 필드로 카드를 내는 일을 전투 상태가 처리한다

선행: R2-64 │ 후행: R2-66 │ 산출물: BattleCommand, BattleEvent, BattleCommandHandler │ Type: Rule │ Domain: Battle Hand

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 카드를 한 장 낼 때 화면이 여섯 줄을 순서대로 부른다. 하나만 빠져도 어긋난다
        - 덱에서 뽑는 일도 세 곳에서 각자 같은 순서를 적고 있다
        - 이 화면은 전투의 손패를 안 쓰고 자기 배열만 든다. 전투의 손패가 비어 있다
    - 목적
        - 사용자가 한 일 하나를 전투가 받아 끝까지 처리하고, 무슨 일이 있었는지 돌려주게 한다
    - 기대 결과
        - 화면은 하나만 보내고 돌려받은 것만 보고 그린다
        - 순서를 화면이 조립하지 않는다
    - 건드리지 않는 것
        - 카드 능력 - R2-66
        - 공격과 스킬 - R2-67
        - 카드가 어디에 떨어졌는지 - 화면에서만 알 수 있다

2. 보내는 것과 돌려받는 것의 모양을 만든다
    - 보내는 것은 사용자가 하는 일 하나다
    - 돌려받는 것은 일어난 일의 목록이다. 일어난 차례대로다
    - 한 번에 안 끝나는 카드가 있어서 목록이어야 한다

3. 카드에 적혀 있는 것은 밖에서 받는다
    - 어떤 종류인지, 체력이 얼마인지는 카드에 적혀 있다. 판과 무관하다
    - 전투가 그것까지 들면 판마다 카드 백 장을 통째로 적어 두게 된다

4. 화면이 전투의 손패를 쓰게 한다
    - 시작할 때 전투의 손패에도 같은 카드를 넣는다
    - 신원은 화면 카드의 번호를 쓴다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 카드 뽑기, 필드에 내기
    - 못 내는 카드가 필드에 놓이지 않는지

# Issue

1. 전투의 손패가 비어 있었다
    - 증상
        - R2-57 에서 손패를 전투로 옮겼는데, 이 화면은 전투의 손패를 한 번도 안 쓰고 자기 배열만 들고 있었다
    - 원인
        - 그때는 옮길 대상이 본편 쪽 저장소였다. 이 화면은 처음부터 자기 배열로 만들어져 있었다
    - 처리
        - 시작할 때 전투의 손패에도 넣게 했다. 그래야 전투가 [손패에 있는 카드인가] 를 판단할 수 있다
        - **판단을 안으로 옮기려면 판단에 쓸 값이 먼저 안에 있어야 한다**

2. 명령을 보내는 자리를 잘못 잡을 뻔했다
    - 증상
        - 처음에 떨어진 자리를 안 보고 바로 명령을 보냈다. 필드 밖에 떨어뜨려도 카드가 놓인다
    - 원인
        - 판단을 전부 전투로 보내려다 화면만 아는 것까지 보냈다
    - 처리
        - 떨어진 자리는 화면이 보고, 낼 수 있는 카드인지는 전투가 보게 나눴다
        - **화면에서만 알 수 있는 것은 화면이 판단한다.** 전부 안으로 보내는 것이 목적이 아니다

3. 같은 판단이 두 곳에 생길 뻔했다
    - 증상
        - 화면이 [유닛인가] 를 보고 있었는데 전투도 같은 것을 본다
    - 원인
        - 옮기면서 옛 줄을 안 지웠다
    - 처리
        - 화면 쪽을 지웠다. 전투가 안 된다고 하면 화면은 그것만 보면 된다
        - **판단을 옮겼으면 옛 판단을 지운다.** 남겨 두면 둘 중 하나가 먼저 낡는다
