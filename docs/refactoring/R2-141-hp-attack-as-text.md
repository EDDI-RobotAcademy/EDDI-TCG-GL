# Issue

1. 맞을 때까지 다섯 번 고쳤다 — 전부 사용자가 찾았다
    - 고친 차례
        - 자리 — **색 영역 무게중심**으로 잡았다. 방울은 아래가 넓어 색 무게중심이 아래로
          쏠리는데 글자는 그보다 더 아래에 있다. 글자를 재야 했다
        - 자리 — 흰 글자를 집을 때 **배지 테두리 반사광**까지 셌다. 사방이 색으로 둘러싸인
          점만 세도록 고쳤다
        - 자리 — 세로 기준을 `textBaseline: middle` 로 잡았다. 그 상자에는 아래로 내려가는
          획 자리가 들어 있어서 **숫자만 그리면 위로 뜬다.** 먹 자국 기준으로 바꿨다
        - 굵기 — 굵은 Arial 로 그렸다. 원본은 **굵고 얇은 획 차이가 큰 세리프**다. 그림자도
          넣었는데 원본에 없다
        - 크기 — **배지를 거쳐서** 쟀다. 빈 그림과 숫자 그림은 배지 크기가 2.4% 다르고 그
          차이가 섞여 들어왔다. 자리는 배지를 거쳐야 맞지만 크기는 판에서 바로 재야 한다
    - 진짜 원인
        - **눈으로 대 보지 않고 재기만 했다.** 사용자가 [인게임에 이미지를 올려놓고
          비교해보라고] 한 뒤에야 겹쳐 보는 판을 만들었다
        - 한 번에 한 값씩 고치면서, 무엇이 틀렸는지를 매번 새로 추측했다
    - 처리
        - **보기를 맞추는 일은 겹쳐 놓고 시작한다.** 재는 것은 그 다음이다
        - 겹쳐 보는 판이 있으면 자리·크기·굵기·자간이 한 화면에서 따로 조정된다

2. 숫자만 제자리에 남고 무기가 혼자 날아갔다 — 사용자가 찾았다
    - 원인
        - 숫자를 배지의 **형제**로 붙였다. 그림에 숫자가 박혀 있을 때는 한 덩어리였다
    - 처리
        - 배지의 **자식**으로 붙인다. 연출이 `position` 과 `rotation` 만 건드리므로
          날아가는 것도 도는 것도 그대로 따라간다
        - **한쪽만 형제로 두면 나중에 그 배지가 움직일 때 또 난다.** 체력도 같이 고쳤다

3. 겉보기를 맞추려고 칸을 옮겼다가 공격 경로가 바뀌었다 — 사용자가 찾았다
    - 증상
        - 「칼이 이전보다 더 나가는 것 같다」
    - 원인
        - 빈 바탕 그림은 그림 안에서 배지가 놓인 자리가 숫자 그림과 다르다
          (검은 가로 2.9% · 세로 2.5%). 그것을 **칸 값으로 보정**했다
        - **연출은 칸 한가운데를 축으로 돌고 거기서 날아간다.** 칸을 옮기면 길이 옮겨 간다
    - 처리
        - 칸을 원래대로 되돌리고 **그림 쪽을 맞췄다.** 빈 그림의 배지가 숫자 그림과 같은
          자리 같은 크기에 오도록 옮겨 담았다
        - **그림이 규칙에 안 맞으면 그림을 고친다.** 코드로 보정하면 그 코드를 쓰는 다른
          것이 같이 틀어진다

4. 화면에 이미 있는 것을 기준으로 안 삼았다
    - 증상
        - 검 숫자가 바로 옆 지팡이 숫자보다 6% 작았다
    - 원인
        - 지팡이는 **아직 그림 그대로**다. 손대지 않은 원본이 화면에 같이 떠 있었는데
          그것과 대 보지 않았다
    - 처리
        - 셋을 **카드 폭 기준**으로 환산해 견줬다. 원본 셋이 0.104~0.109 로 거의 같다
        - **고치지 않은 것이 옆에 있으면 그것이 자다**

## 화면에서 셋이 같은 크기여야 한다

카드 폭을 1 로 놓았을 때 글자 높이다.

| | sizeRatio | 슬롯 높이 | 화면에서 |
| --- | --- | --- | --- |
| 지팡이 | 0.0892 | 1.219 | **0.1087** |
| 검 | 0.1045 | 1.040 | **0.1087** |
| 체력 | 0.2117 | 0.513 | **0.1086** |

지팡이 원본 글자는 0.1040 으로 검보다 4% 작았다. 원을 검에 맞추면서 글자도 맞췄다 —
**원이 같은 크기인데 글자만 다르면 더 튄다.**

## 바탕 그림을 옮겨 담았다

받은 빈 그림은 배지가 숫자 그림과 다른 자리에 있었다. 그대로 쓰면 배지가 통째로
옮겨 앉는다. 숫자 그림과 같은 자리 같은 크기가 되도록 다시 만들었다.
받은 원본은 `*_source.png` 로 남겼다.

```
ffmpeg -f lavfi -i "color=c=black@0.0:s=619x1022,format=rgba" -i sword_power_source.png \
  -filter_complex "[1]scale=628:1037[s];[0][s]overlay=x=-23:y=18" -pix_fmt rgba sword_power.png

hp            s=328x546    scale=324:537    overlay x=-1  y=8
staff_power   s=634x1227   scale=664:1285   overlay x=-17 y=-20
```

지팡이는 **검의 원 자리·크기**를 목표로 잡았다. 나란히 놓았을 때 같아 보이라는 것도
그림에 넣었다 — 칸으로 맞추면 공격 경로가 달라진다.

## 무기가 표적 앞에서 멈춘다

```
AttackAnimationV2.WEAPON_STOP_SHORT = 0.35   // 카드 폭 대비
```

전에는 표적 한가운데까지 날아갔다. 이펙트도 거기서 터지므로 **칼날이 이펙트를 타고
넘어**, 이펙트가 칼 중간에서 나오는 것처럼 보였다. 이펙트 자리는 안 건드리고 무기가
덜 나가는 것으로 맞췄다.

## 자리는 배지 기준, 크기는 판 기준

**빈 그림과 숫자 그림은 배지가 놓인 자리도 크기도 다르다** (검은 자리 2.9%, 크기 2.4%).

```
자리   숫자 그림에서  글자가 [배지 한가운데]에서 얼마나 떨어져 있나
       빈 그림에서    배지가 [판] 어디에 있나
       둘을 합쳐      판 기준 자리를 낸다

크기   판에서 바로 잰다.  배지를 거치면 배지 크기 차이가 섞인다
```

둘을 같은 방식으로 재려다 크기가 6% 틀어졌다.

## 글자를 놓는 기준

`textBaseline: 'middle'` 은 **글꼴 상자**를 가운데 맞춘다. 그 상자에는 `g` `y` 처럼 아래로
내려가는 획 자리가 들어 있어서, **숫자만 그리면 글자가 위로 뜬다.**

`actualBoundingBox` 로 실제 먹이 묻은 칸을 재서 그 가운데를 맞춘다. 크기도 먹 자국으로
맞춰서, **글꼴을 바꿔도 글자 크기가 안 변한다.**
