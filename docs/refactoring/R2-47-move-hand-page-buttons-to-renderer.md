# [ETWGL-R2-47] 손패 페이지 버튼을 만드는 일을 렌더러로 옮긴다

선행: R2-27 │ 후행: R2-59 │ 산출물: HandPageButtonsRendererV2 를 본편이 쓴다 │ Type: Rendering │ Domain: Battle Hand

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 손패 아래의 이전 / 다음 버튼을 저장소가 직접 만들고 있었다
        - 저장소는 값을 들고 있는 곳이지 화면에 그리는 곳이 아니다
        - 렌더러는 이미 있었는데 확인용 화면 하나만 쓰고 본편은 옛 길을 갔다
    - 목적
        - 본편과 확인용 화면 셋이 모두 렌더러를 거치게 한다
    - 기대 결과
        - 버튼을 만드는 곳이 한 군데가 된다
    - 건드리지 않는 것
        - 버튼을 눌렀을 때의 동작 - 누름 감지는 화면 비율로 잡은 네모를 쓴다. 버튼 그림과 무관하다
        - 저장소에 남은 옛 버튼 만들기 코드 - 부르는 곳은 없앴다. 코드 지우기는 R2-59 에서 낡은 손패 저장소를 정리할 때 함께 한다

2. 화면에 보이는 모습이 달라지지 않아야 한다
    - 버튼의 자리, 크기, 화면 크기를 바꿨을 때의 비율이 전과 같아야 한다
    - 옮기는 일이지 고치는 일이 아니다

3. 옛 계산과 새 계산을 나란히 놓고 다른 곳을 찾는다
    - 자리를 잡는 계산은 두 쪽이 같았다
    - 크기를 재는 계산은 부호가 달랐다
    - 화면 크기가 바뀔 때의 처리가 달랐다. 한쪽은 배율을 곱하고 한쪽은 새로 만들었다

4. 본편과 확인용 화면을 모두 옮긴다
    - 본편 하나와 확인용 화면 셋
    - 옛 버튼 만들기 코드를 부르는 곳이 없어야 한다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 전투 화면을 쓰는 확인용 화면이 전부 뜨는지
    - 본편, 페이지 넘김, 안내 문구, 필드 에너지

# Issue

1. 배율로 크기를 맞추다가 화면 비율이 깨졌다
    - 증상
        - 옮기고 나니 화면 크기를 바꿀 때 버튼이 넘치거나 모자랐다
    - 원인
        - 렌더러가 만들 때의 크기를 기준으로 삼고, 자리를 잡을 때 그 기준에 배율을 곱했다
        - 만드는 시점과 자리를 잡는 시점의 화면 크기가 다르면 기준이 어긋난다
        - 한 번 어긋나면 그 뒤로 계속 어긋난 값에 곱해진다
    - 처리
        - 배율을 안 쓰고 그때그때 판을 다시 만든다
        - **기준을 저장해 두고 곱하는 방식은, 기준이 언제 정해지는지까지 봐야 한다**

2. 옛 계산에 맞췄더니 화살표가 거꾸로 되었다
    - 증상
        - 크기 계산을 옛 방식과 똑같이 맞췄더니 이전 버튼이 오른쪽을, 다음 버튼이 왼쪽을 가리켰다
    - 원인
        - 옛 방식은 시작점에서 끝점을 빼서 음수를 넘긴다
        - 크기가 음수이면 판이 뒤집혀 그림이 180도 돌아간다
        - 두 버튼 그림이 좌우 대칭이라 서로 바뀐 것처럼 보였다. 그래서 오래 눈치채지 못했다
    - 처리
        - 크기는 두 모서리 사이의 거리로 잰다. 부호를 남기지 않는다
        - **옛것에 맞추는 것과 옛것의 잘못까지 물려받는 것은 다르다.** 옛 화면이 맞는지부터 본다

3. 옮기고도 버튼 누름이 그대로 동작한 이유
    - 증상
        - 버튼을 만드는 쪽을 통째로 바꿨는데 누름은 아무것도 안 고쳤는데 동작했다
    - 원인
        - 누름 감지는 그려진 것을 맞히는 방식이 아니다. 화면 비율로 잡아 둔 네모 안에 들어왔는지만 본다
        - 그래서 누구가 그렸는지와 상관이 없다
    - 처리
        - 이번에는 이득이었다. 다만 그림과 누름 네모가 따로 놀기 때문에 한쪽만 옮기면 어긋난다
        - **버튼 자리를 옮길 일이 생기면 두 곳을 같이 고쳐야 한다**
