# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - battle 아래로 옮길 전투 폴더가 38개인데 한 번도 옮겨본 적이 없다
        - 폴더를 옮기면 참조가 몇 개 깨지고 고치는 데 얼마나 걸리는지 모른다
        - 완료 확인 목록을 만들어놓고 아직 한 번도 실행해보지 않았다. 항목이 충분한지 과한지 모른다
        - 검증 없이 큰 묶음부터 옮기면 문제가 생겼을 때 원인이 이관 방식인지 그 폴더 특성인지 구분할 수 없다
    - 목적
        - 가장 안전한 네 폴더를 먼저 옮겨 폴더 이동만으로 실제 개선이 있는지 확인한다
        - 이관 비용과 확인 시간을 재서 다음 묶음의 크기와 방식을 정할 근거로 삼는다
    - 기대 결과
        - 폴더만 옮기는 방식이 통하는지 알고 나머지 여섯 건을 시작한다
        - 효과가 없다면 다음 묶음부터 이동과 정리를 함께 하도록 계획을 바꾼다
        - 확인 목록이 동작이 달라진 것을 실제로 잡는지 알고 시작한다
    - 왜 이 네 폴더인가
        - 밖에서 이 넷을 참조하는 파일이 시나리오 하나뿐이다. 38개 폴더 중 가장 적다
        - 넷이 같은 구성이다. 패널과 팝업, 카드 목록 저장소로 되어 있다
        - 덱은 함께 옮기지 않는다. 화면이 없고 드로우의 출처라 손패와 성격이 같다
    - 건드리는 것
        - your_tomb, opponent_tomb, your_lost_zone, opponent_lost_zone 네 폴더의 위치
        - 이 넷을 참조하는 시나리오의 경로
        - 이 넷이 밖을 참조하는 상대 경로
        - BEHAVIOR_CHECK.md - 실행해보고 항목이 모자라거나 과하면 고친다
    - 건드리지 않는 것
        - 폴더 안의 코드 - 위치와 경로만 바꾼다. 내용을 함께 고치면 동작이 달라졌을 때 이동 탓인지 수정 탓인지 알 수 없다
        - 저장소 파일 8개 (네 폴더가 각각 인터페이스와 구현체를 하나씩 갖는다) - 무덤과 로스트존의 카드 목록은 재접속 시 복원해야 하는 값이라 나중에 전투 상태로 흡수된다. 지금 이름을 바꾸면 그때 또 옮기게 된다
        - your 와 opponent 중복 - 렌더러와 화면 배치가 거의 같지만 통합하지 않는다. 전투 상태가 한 곳으로 모인 뒤에 하면 병합할 로직이 거의 없어진다
        - 폴더 이름 - 옮기기만 한다. 이름 정리는 다음 작업에서 한다
        - 아직 옮기지 않은 전투 폴더 34개 - 이 작업에서 잰 수치를 보고 다음 묶음을 정한다

2. 네 폴더를 옮기고 끊어진 참조를 잇는다
    - R2-5 에서 정한 자리로 옮긴다
    - 이력이 끊기지 않게 옮긴다. 지우고 새로 만들면 누가 왜 그렇게 짰는지 추적할 수 없게 된다
    - 시나리오가 이 넷을 참조하는 20회의 경로를 고친다
    - 이 넷이 손패와 공용 코드를 참조하는 상대 경로가 깊어진다. 함께 고친다
    - 넷끼리 참조하는 경로를 고친다

3. 이관이 성립하는지 확인한다
    - 타입 검사와 의존 검사가 통과한다
    - 옮긴 자리가 R2-3 의 의존 규칙을 어기지 않는다
    - 파일 이력이 이어져 있다
    - 되돌리기를 실제로 한 번 해본다. 안전망이 있다는 것과 써본 것은 다르다

4. 확인 절차를 처음 돌려보고 다듬는다
    - BEHAVIOR_CHECK.md 아홉 항목을 실제로 실행한다
    - 걸리는 시간을 잰다. 앞으로 여섯 번 이상 반복할 절차다

    - 옮긴 뒤에도 남아 있는 문제를 그대로 적는다. 저장소 파일 8개와, your 와 opponent 로 갈라진 폴더 2쌍(무덤, 로스트존)
    - 폴더 이동만으로 나아진 것이 있는지, 있다면 무엇인지 판단한다
    - 나아진 것이 없다면 다음 묶음부터 이동과 정리를 붙이도록 계획을 고친다. 이 판단이 나머지 여섯 건의 방식을 정한다

# Issue

1. 이력 확인 방법을 잘못 잡았다
    - 증상
        - To-do 에 git log --follow 로 이력이 이어지는지 확인한다고 적었는데 결과가 0개로 나왔다
    - 원인
        - --follow 는 커밋된 이력을 따라간다. 아직 커밋 전이라 따라갈 이력이 없다
        - 확인 시점을 생각하지 않고 항목을 적었다
    - 처리
        - git 이 25개 파일을 전부 rename 으로 인식한 것으로 대신 확인했다
        - 실제 --follow 확인은 커밋 후에 해야 한다. 항목을 커밋 이후로 옮긴다

2. 되돌리기 시험을 하지 못했다
    - 증상
        - To-do 에 되돌리기를 한 번 시험한다고 적었으나 하지 못했다
    - 원인
        - 커밋 전에는 되돌리기가 작업을 지우는 것과 같다. 시험할 수단이 없다
        - 이 항목도 커밋 이후를 전제로 하는데 커밋 전 단계에 넣었다
    - 처리
        - 커밋 후로 옮긴다. 이관 작업의 To-do 는 커밋 전과 후를 나눠 적어야 한다

3. 폴더를 옮겨도 고칠 곳이 줄지 않았다

        - 무덤 관련 코드를 고칠 때 여는 폴더 수가 이동 전 4개, 이동 후 4개로 같다
