# [ETWGL-R2-62] 연출 도중 종료되어도 전투 상태가 일관되도록 처리 순서 분리

선행: R2-61 │ 후행: R2-63 │ 산출물: 상태를 연출 앞에서 다 바꾸는 규칙 │ Type: Rule │ Domain: Battle

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 카드 효과가 상태를 바꾸다 말고 연출을 기다린 뒤 나머지를 바꾼다
        - 기다리는 동안 화면이 닫히면 체력만 0 이고 필드에는 그대로 서 있는 상태가 된다
        - 무덤에도 없고 필드에서도 안 빠진 카드가 생긴다
    - 목적
        - 상태를 바꾸는 일을 연출 앞으로 모은다
    - 기대 결과
        - 연출 도중 화면이 닫혀도 전투를 적어 두면 앞뒤가 맞는다
    - 왜 이제야 할 수 있나
        - 앞서 두 번 미뤘다. 본편에 상태를 바꾸는 코드가 없어서 갈라낼 것이 없었다
        - R2-60, R2-61 에서 체력과 유닛 상태가 전투로 들어온 뒤에야 다룰 것이 생겼다
    - 건드리지 않는 것
        - 화면을 고치는 시점 - 연출이 끝난 뒤 그대로다. 보이는 것이 달라지면 안 된다
        - 연출 자체 - 시간과 모양을 안 건드린다

2. 규칙을 정한다
    - 상태는 연출을 기다리기 전에 다 바꾼다
    - 화면 정리는 연출이 끝난 뒤에 한다
    - 이 둘을 섞지 않는다

3. 갈라진 곳을 찾는다
    - 효과 함수마다 기다리는 줄 뒤에 상태를 바꾸는 줄이 있는지 본다
    - 기다리는 것이 사이에 없으면 갈라진 것이 아니다

4. 늘 붙어 다니는 두 줄을 하나로 묶는다
    - 무덤으로 보내는 것과 필드에서 빼는 것이 여덟 군데에서 늘 함께 있었다
    - 둘 사이에서 화면이 닫히면 무덤에는 있는데 필드에도 남는다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 죽음의 낫, 에너지 번, 시체 폭발
    - 연출이 다 나온 뒤에 유닛이 사라지는지가 핵심이다

# Issue

1. 두 번 미룬 뒤에야 할 수 있었다
    - 증상
        - 이 일이 원래 R2-58 자리였는데, 본편에 상태를 바꾸는 코드가 한 줄도 없었다
        - 규칙이 전부 확인용 화면 안에 있었다
    - 원인
        - 계획을 세울 때 본편에 규칙이 있다고 여겼다
    - 처리
        - 능력의 수치를 꺼내고, 본체와 유닛 상태를 전투로 옮긴 뒤에 다뤘다
        - **다룰 것이 없는 작업은 미루는 것이 아니라 그 앞의 것을 찾아 먼저 한다**

2. 여섯 중 넷만 진짜 갈라진 것이었다
    - 증상
        - 기다리는 줄 뒤에 상태를 바꾸는 줄이 있는 곳이 여섯이었다
    - 원인
        - 둘은 상태 변화끼리 붙어 있었다. 그 사이에 기다리는 것이 없다
    - 처리
        - 넷만 고쳤다. 붙어 있는 것을 굳이 옮기면 읽기만 나빠진다
        - **기다리는 줄 뒤에 있다고 다 갈라진 것이 아니다.** 사이에 기다리는 것이 있는지를 본다

3. 시체 폭발은 연출 도중에 상태가 바뀐다
    - 증상
        - 날아온 것이 맞을 때마다 체력이 깎이는데, 무덤에 넣는 것은 연출이 다 끝난 뒤였다
    - 원인
        - 화면에서 사라지는 것을 연출 끝에 맞추다 보니 상태 변화까지 같이 끌려갔다
    - 처리
        - 맞을 때 바로 무덤에 넣고, 화면에서 감추는 것만 연출 뒤에 남겼다
        - **화면을 언제 고칠지와 상태를 언제 바꿀지는 따로 정한다**
