# [ETWGL-R2-56] 필드에 놓인 카드를 전투 상태 안으로 옮긴다

선행: R2-55 │ 후행: R2-57 │ 산출물: Battle 이 내 필드와 상대 필드를 들고 있다 │ Type: Rule │ Domain: Battle Field

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 필드가 저장소 넷에 흩어져 있다. 한 장씩의 속사정을 담는 둘, 전체 배치를 담는 둘
        - 같은 것을 두 군데에 나눠 들고 있어서 서로를 모른다
        - 배치 쪽은 자리와 신원이 한 값이라 R2-55 에서 고친 것과 같은 문제를 갖고 있다
        - 상대 필드의 시작 카드 다섯 장이 저장소 생성자 안에 있다. 값을 담는 곳이 시나리오를 정하고 있었다
    - 목적
        - 넷을 필드라는 한 개념으로 모아 전투 한 판 안에 둔다
    - 기대 결과
        - 전투를 통째로 적으면 필드에 놓인 카드와 그 차례가 함께 적힌다
        - 필드에서 카드가 빠져도 빈 자리가 안 생긴다
    - 건드리지 않는 것
        - 필드를 그리는 것 - 화면이다
        - 화면 좌표 번호 - 도메인 값이 아니지만 손패도 같은 방식이라 함께 걷어내야 한다. R2-57
        - 손패 - R2-57

2. 도메인으로 보면 넷이 하나다
    - 한 장씩의 속사정과 전체 배치는 따로 있을 것이 아니다
    - 필드가 [어떤 카드가 어떤 차례로 놓여 있는가] 를 들면 둘이 하나가 된다
    - 내 것과 상대 것은 같은 규칙이므로 안쪽을 함께 쓰고, 밖으로 내는 길만 갈라 낸다

3. 순서는 목록이 들고 신원과 상관없게 한다
    - 새로 오는 것은 맨 뒤다. 부활도 새로 나오는 것과 같다
    - 필드가 13, 20, 33 일 때 17 이 부활하면 13, 20, 33, 17 이다
    - 중간이 빠지면 뒤엣것이 당겨진다. 빈 자리를 안 남긴다

4. 시나리오 값을 저장소에서 빼낸다
    - 상대 필드의 시작 카드 다섯 장을 부르는 쪽으로 옮긴다
    - 실제 대전에서는 서버가 줄 값이다
    - R2-51 에서 상대 덱을 다룬 방식과 같다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 상대 필드, 손패에서 필드로, 스킬, 붙은 표시

# Issue

1. 저장소를 하나씩 옮기려다 개념이 하나인 것을 놓칠 뻔했다
    - 증상
        - 저장소가 넷이라 티켓도 넷으로 가르려 했다
    - 원인
        - 담는 그릇의 개수로 셌다. 그릇이 넷이라 개념도 넷으로 보였다
    - 처리
        - 도메인으로 보니 하나였다. 한 장씩의 속사정과 전체 배치는 같은 것을 나눠 든 것이다
        - **몇 개로 나눌지는 담는 그릇이 아니라 개념으로 센다**

2. 값을 담는 곳이 시나리오를 정하고 있었다
    - 증상
        - 상대 필드 저장소의 생성자가 카드 다섯 장을 스스로 넣고 있었다. 본편이 상대 필드에 늘 그 다섯 장을 그린 이유다
    - 원인
        - 서버가 없어서 어딘가에 값을 둬야 했는데 저장소 안에 뒀다
    - 처리
        - 부르는 쪽으로 옮기고 서버가 줄 값이라고 적었다
        - **없는 것을 임시로 채울 때는 채우는 자리를 밖에 둔다.** 안에 두면 그것이 기본값이 된다

3. 선언을 지우는 정규식이 줄바꿈까지 먹었다
    - 증상
        - 저장소 선언을 지웠더니 다음 줄이 앞줄 끝에 붙어 버렸다. 네 파일에서 났다
    - 원인
        - 지우는 무늬 끝에 줄바꿈이 안 들어가 있었다
    - 처리
        - 붙어 버린 자리를 다시 떼어 놓았다
        - **줄 단위로 지울 때는 지운 자리에 줄바꿈이 남는지 본다.** 규칙 17 에 붙일 만한 것이다
