선행: R2-130 │ 후행: R2-132 │ 산출물: 전투와 같은 모양의 로비 │ Type: Structure │ Domain: Platform

# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - 앱 안에 만드는 방식이 둘이다 — 전투는 값·그리기·다루기가 갈려 있고, 로비·상점·내 카드는 화면 파일 하나에 다 들어 있다

# Issue

1. 로비로 돌아올 때마다 단추를 새로 만들고 있었다
    - 증상
        - 다른 화면에 갔다 로비로 오면 그림 넷을 다시 읽고 물건을 다시 만들었다
    - 원인
        - 떠날 때 단추를 지우고 돌아올 때 다시 만드는 구조였다. 누름 처리기도 그때마다 다시 붙였다
        - 옮기기 전에는 만드는 곳과 지우는 곳이 화면 파일 안 다른 자리에 있어서 둘이 짝이라는 것이 안 보였다
    - 처리
        - 한 번 만들고 보이기만 바꾼다
        - **만들기와 지우기가 멀리 떨어져 있으면 둘이 짝인지 안 보인다.** 한 곳으로 모으니 [왜 지웠다 다시 만드나] 가 바로 보였다

2. 창 크기 다시 재기가 전투 안에 있었다
    - 증상
        - 로비가 그것을 쓰려면 `src/battle/` 을 들여와야 한다
    - 원인
        - 전투에서 만들었고 전투만 쓰고 있었다. 이름에 battle 이 없는데 자리가 battle 안이었다
    - 처리
        - `src/core/` 로 옮겼다. 전투 쪽 들여오는 줄 다섯만 바뀌었다
        - **전투에서 만든 것이라고 전투의 것은 아니다.** 창 크기에서 제 크기를 내는 일은 어느 화면이나 한다

## 전투에서 가져온 것과 안 가져온 것

| | 가져왔나 | 왜 |
| --- | --- | --- |
| 값은 frame, THREE 물건은 renderer | ⭕ | 뿌옇던 원인도 여기서 갈린다 |
| 만들기·누름·크기 조절을 함께 | ⭕ | 이 저장소에서 가장 자주 난 버그가 크기 조절을 잊는 것이다 |
| 만드는 자리에서 크기 조절 등록 | ⭕ | 같은 이유 |
| 누름 순서 다루기 | ✗ | 로비는 단추 넷뿐이다. 가릴 순서가 없다 |

**전투 것을 다 가져오지 않았다.** 로비에 없는 문제를 푸는 장치는 안 가져온다.

## 자리값을 비율로

```
전:  new THREE.Vector2(-400, -200)   1920x1080 기준 점. 창이 바뀌면 다시 센다
후:  xRatio: -400/1920               비율. 렌더러가 곱하기만 한다
```

프레임이 THREE 를 모르게 되는 것이 함께 따라온다 (`frame-no-three`).
