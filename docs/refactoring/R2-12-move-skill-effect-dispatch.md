# Success criteria

1. 왜 하는지와 어디까지 할지를 정한다
    - 문제
        - R2-11 에서 핸들러를 옮기고 나니 스킬 폴더에 파일 이름이 Animation 인 것 넷이 남았다
        - 그중 둘은 연출이 아니었다. 카드 번호를 보고 어느 효과를 부를지 고르는 배선이다
        - 파일 안 주석에도 적혀 있다. 마검의 지배자 네더 블레이드가 공격자일 때 전용 효과를 부른다
        - 이름이 Animation 이라 연출로 보이는데, 실제 그림은 animation/nether_blade/ 에 있다
    - 목적
        - 배선 둘을 그것을 부르는 핸들러와 같은 자리로 옮긴다
    - 기대 결과
        - 스킬 버튼을 눌렀을 때 무엇이 도는지를 한 폴더에서 본다
        - 이름이 Animation 이라도 연출이 아니라는 것이 폴더 이름으로 드러난다
    - 옮기는 것
        - FirstSkillAnimation (109줄), SecondSkillAnimation (162줄)
    - 건드리지 않는 것
        - 파일 이름 - 이동과 이름 변경을 섞으면 무엇 때문에 깨졌는지 가릴 수 없다. 어차피 R2-33 에서 CardAbility 의 effect 로 대체되며 사라진다
        - AttackAnimationV2 (2,301줄), GeneralAttackAnimation (268줄) - 진짜 연출이다. src/animation/ 으로 가야 하는데, 그 폴더 자체가 R2-15 에서 battle 로 옮겨진다. 먼저 옮기면 두 번 옮기게 된다. **R2-15 범위에 넣는다**
        - 파일 안의 코드 - 위치와 경로만 바꾼다

2. 배선 둘을 핸들러 옆으로 옮긴다
    - 핸들러가 effect/ 를 부르는 구조로 만든다
    - 폴더 이름으로 성격을 드러낸다. handler 는 화면에서 무엇을 움직이는가, effect 는 어느 카드 효과를 부르는가

3. 끊어진 참조를 잇고 빈 폴더를 정리한다
    - 핸들러 둘이 배선을 부르는 경로를 고친다
    - first_skill, second_skill 폴더가 비면 지운다

4. 이관이 성립하는지 확인한다
    - 타입 검사와 의존 검사가 통과한다

5. 게임 동작이 달라지지 않았는지 확인한다
    - 개발 서버를 다시 켜고 확인한다
    - 시나리오는 이 배선을 쓰지 않는다. 네더 블레이드 효과를 직접 부른다. 변화가 없어야 정상이다
